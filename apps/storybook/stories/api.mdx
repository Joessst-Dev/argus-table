## Events

A change of state fires `argus-<property>-change`, with the new value under the property's name in `detail`, then what caused it. The wrappers bind these two ways (`v-model:sorting`, `[(sorting)]`).

| Event                            | Constant                   | `detail`                                          | Fires                                                                                                           |
| -------------------------------- | -------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| `argus-sorting-change`           | `SORTING_CHANGE`           | `{ sorting }`                                     | A sortable header was clicked, or Enter or Space pressed on it                                                  |
| `argus-column-sizing-change`     | `COLUMN_SIZING_CHANGE`     | `{ columnSizing, columnId, width }`               | A resize: a drag (every frame), Alt+Arrow, a double-click on the handle or `autosizeColumns()`; once per column |
| `argus-column-order-change`      | `COLUMN_ORDER_CHANGE`      | `{ columnOrder, columnId, groupId? }`             | A column or group moved: a header drag (on drop) or Alt+Shift+Arrow; `groupId` for a group                      |
| `argus-column-pinning-change`    | `COLUMN_PINNING_CHANGE`    | `{ columnPinning, columnId, pin }`                | A column was pinned or unpinned (`pin: false`) through a plugin such as the column menu                         |
| `argus-column-visibility-change` | `COLUMN_VISIBILITY_CHANGE` | `{ columnVisibility, columnId, visible }`         | A column was hidden or shown through a plugin                                                                   |
| `argus-column-filters-change`    | `COLUMN_FILTERS_CHANGE`    | `{ columnFilters, columnId, columnFilter }`       | A column's filter was set, changed or cleared (`columnFilter: undefined`) through a plugin                      |
| `argus-selection-change`         | `SELECTION_CHANGE`         | `{ selection }`                                   | A click on a row, Space, Shift+Arrow, Shift+PageUp/PageDown or Ctrl/Cmd+A, with a `selectionMode`               |
| `argus-cell-click`               | `CELL_CLICK`               | `{ row, rowId, index, columnId, value, pinned? }` | A click in a body or pinned-row cell, or Enter on it; `pinned` is set for a pinned row                          |
| `argus-row-click`                | `ROW_CLICK`                | `{ row, rowId, index, pinned? }`                  | A click in a body or pinned row, after `argus-cell-click`                                                       |
| `argus-range-change`             | `RANGE_CHANGE`             | `{ first, last }`                                 | After an update that changed the rows in view (both inclusive)                                                  |
| `argus-load-error`               | `LOAD_ERROR`               | `{ error, start, end }`                           | After a `dataSource` page failed to load (`end` exclusive)                                                      |

## Controlled and uncontrolled state

`sorting`, `columnSizing`, `columnOrder`, `columnPinning`, `columnVisibility`, `columnFilters` and `selection` work either way. Leave them unset and the table keeps its own state, then fires the event. Set them and the table only proposes: it fires the event right away with the proposed state and waits for you to set the property. Uncontrolled, the event fires after the update that applied the change. Set them back to `undefined` to hand control back to the table.

## Saving a layout

`getState()` returns that state, plus `quickFilter` and the scroll position, as one object of plain JSON; `setState(state)` restores it (see Features/Saved state). It applies only the keys it's given, leaves the ones you control alone, keeps the others uncontrolled and fires no events.

```js
const KEY = 'orders-table';
await table.setState(JSON.parse(localStorage.getItem(KEY) ?? '{}'));
addEventListener('pagehide', () => {
  localStorage.setItem(KEY, JSON.stringify(table.getState()));
});
```

## Other languages

The built-in text is English: accessible names, the Retry button, "No rows" and the screen-reader announcements. `labels` translates it, and `headerMenu({ labels })`, `formulas({ labels })` and `tableExport({ labels })` do the same for the add-ons (see Features/Labels, which sets every key in German). Keys left out stay English. Text with values in it is a function, so it can choose a plural form:

```js
table.labels = {
  selectRow: 'Zeile auswählen',
  rowCount: ({ count }) => (count === 1 ? '1 Zeile' : `${count} Zeilen`),
};
```

## Plugins

`plugins` takes add-ons, such as the column menu from `@argus-table/header-menu` (see Add-ons/Header menu) and formula columns from `@argus-table/formulas` (see Add-ons/Formulas: a column with `formula: '[price] * [qty]'` computes its value per row, and with `editing: 'edit'` users add and edit them from the column menu) and export to CSV, Excel and PDF from `@argus-table/export` (see Add-ons/Export). A plugin is an object with a `name` and any of these hooks:

```ts
import type { ArgusPlugin } from 'argus-table';

const plugin: ArgusPlugin<Order> = {
  name: 'my-plugin',
  // While the table is connected; return a cleanup.
  connect(host) {
    return () => {};
  },
  // Change the column definitions before the table reads them.
  columns: (defs, host) => [
    ...defs,
    { id: 'gross', header: 'Gross', accessor: (o) => o.total * 1.19 },
  ],
  // A key on a focused header or cell, before the table: return true to claim it.
  keydown: (event, target, host) => false,
  // Whether this plugin makes a column's cells editable (marks the others aria-readonly).
  editable: (columnId, host) => false,
};
table.plugins = [plugin];
```

The `host` reads resolved columns (`column(id)`), finds the header or cell of an event (`cellOf(event)`), sorts (`setSort(id, 'asc' | 'desc' | undefined)`, under the `sorting` rules), focuses a header or a cell (`focusHeader(id)`, `focusCell(index, columnId, section?)`), announces to screen readers (`announce(message)`), runs the `columns` hooks again (`invalidateColumns()`), re-renders (`requestUpdate()`) and reads rows: the body in the current order or a pinned side (`row(index, section?)`, `rowCount(section?)`, `rowId(index, section?)`, a column's value with `value(index, columnId, section?)`, or with `readValue(row, columnId, index)` for a row the plugin has itself), and the group header rows (`headerGroups()`). It also pins, hides and filters columns (`setPin`, `setHidden`, `setFilter`), lists them (`columns()`), and wraps a column's own content for a plugin's template (`content(value)`, or `header(def)` for a column's or group's own header), or names it as plain text (`headerText(def)`): every member is always there. The table itself is `host.element`. Plugins run in array order; one that throws is reported in the console and skipped.

### Header text and column meta

A `header` function gets a context: `{ columnId, text }` for a column, `{ groupId, text }` for a group. The table renders it with `text: false`. With `text: true` the table or a plugin asks for the name as plain text, for the column menu's "Hidden columns", an export's header row or an announcement. Return a string then, and a template or framework content (JSX, VNodes) can stay the header:

```ts
{ id: 'total', header: ({ text }) => (text ? 'Total' : html`<b>Total</b> <small>EUR</small>`) }
```

`host.headerText(def)` reads that name (`undefined` for content without one: name the column by its id then). A plugin that wraps headers in its own function forwards text mode: ``header: (context) => (context.text ? host.headerText(def) : html`…`)``.

`meta` on a column holds fields for plugins and the app; the table never reads it, and plugins get it as `host.column(id).meta`. `@argus-table/export` reads `meta.export`. A plugin types its own field by augmenting `ColumnMeta` (with only a framework wrapper installed, augment the wrapper's module instead, such as `'@argus-table/react'`):

```ts
declare module 'argus-table' {
  interface ColumnMeta<TData> {
    total?: { label: string };
  }
}
```
