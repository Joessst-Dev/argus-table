Rows can have child rows: a folder and its files, a manager and their team, a category and its products. Give the table `getSubRows`, a function that returns a row's children (or `undefined` for a row without any), and `data` holds the top-level rows. A row with children gets a toggle in the first data column, and each level is indented under its parent. Child rows are rows like any other: they have cells in every column, and they sort, filter, select, edit and fire click events. Define `getSubRows` once (at module scope, `useCallback`, a class field), and `getParentId` and `getRowId` the same way: a new function on every render builds and sorts the tree again.

Which rows are expanded is `treeExpanded`, a list of row ids, and `argus-tree-expanded-change` reports each change with `{ treeExpanded, rowId, open }`. Leave it unset and the table keeps it: toggles and keys expand and collapse rows, and nothing starts open. Set it and the table is controlled: a toggle or a key only proposes the new ids in the event, and your code applies them. It binds two-way like `selection`. Here the app owns it, starting with src open, and its buttons expand and collapse every folder. Sort by Name or Size: each folder's entries are sorted among themselves and stay under it.

## Row ids and indexes

Without `getRowId`, a top-level row's id is its index in `data`, as in any table, and a child's id is its parent's id, a dot and its index among its siblings: `'0.1'` is the second child of the first row, and `'0.1.2'` the third child of that. These ids are positions: a row added or removed above a row changes its id, and `treeExpanded` and `selection` then name another row. Give `getRowId` when `data` can change, so expanded and selected rows follow their row; its ids are used throughout. Functions that are given a row's index, `getRowId(row, index)` and a column's `accessor(row, index)`, get a child's index counted from `data.length` on, in depth-first order.

Every other index counts the rows shown, in their current order: `scrollToRow(index)`, the click events' `index` and `argus-range-change`. Children of a collapsed row aren't shown, so expanding a row moves the indexes of the rows below it, as a filter does. Cell functions, `rowDetail`, `argus-cell-click` and `argus-row-click` get the row's level as `depth`: `0` for a top-level row, `1` for its children, and so on. It's set only when the rows form a tree.

## Flat data

When every row is in one list and names its parent, give the table `getParentId` instead: it returns the id of a row's parent (an id `getRowId` gives), or `null` for a top-level row. Without `getRowId` the ids are indexes, so it returns the parent's index in `data` as a string. `data` holds every row, and each keeps its index in `data`. A row whose parent isn't found, or that is part of a cycle, shows as a top-level row, with a warning in the console. When both `getSubRows` and `getParentId` are set, `getSubRows` wins, with a warning too.

## Filtering

A filter or the quick filter keeps the rows that match and their ancestors, so a match always shows in its place in the tree. The ancestors show expanded, whatever `treeExpanded` says, and their toggles are disabled until the filter clears; `treeExpanded` itself doesn't change, so clearing the filter brings back the rows people had open. Children of a match aren't kept unless they match too. A row whose children are all filtered out shows no toggle while the filter is on. With a `dataSource` the server filters, and no row opens by itself: see [Children from the server](#children-from-the-server).

## Selecting branches

[Selection](../selection/) works on child rows as on any row: ticking a parent selects the parent only, and select-all selects the rows shown. With `selectBranches` (in `selectionMode: 'multi'`), ticking a row selects its whole branch: the row and every row under it that the filters keep, collapsed or not. A row's id is in `selection` only while its whole branch is selected, so ticking the last child of a row adds the row too, and unticking any child takes out its ancestors. A row with part of its branch selected shows a part-ticked checkbox. Select-all, by the header checkbox or Ctrl+A (Cmd+A on macOS), selects every row the filters keep.

Rows a filter hides are never selected by a tick, and they still count for their parents: a parent's id is in `selection` only when its whole branch is selected, hidden rows included. Under a filter, ticking a parent whose hidden children aren't selected selects the rows shown under it but not the parent itself, and its checkbox shows part-ticked. Clicking it again unticks those rows, at any depth (a folder whose shown files are all selected unticks, and so does the folder above it); once the filter clears, the parent stays part-ticked with only the rows that were ticked selected. So an app that acts on `selection`, deleting the selected rows for example, never reaches rows the user didn't see. The header checkbox counts such a parent as ticked when everything that can be selected under it is. A row the filter keeps while hiding all its children (the row matches, they don't), or with only such rows under it, has nothing to tick while its id needs them: its checkbox is disabled, a click or Space on it selects nothing, and select-all and the header checkbox leave it out (when every row shown is like that, the header checkbox is disabled too). Themes can style it with `::part(selection-checkbox):disabled`.

## Keys

The rows follow the WAI-ARIA treegrid pattern, with the table's [keyboard](../keyboard/) as before. On a cell of the first data column, ArrowRight expands a collapsed row, and ArrowLeft collapses an expanded one. On a collapsed row, a row without children or a row a filter keeps open, ArrowLeft goes to the parent row. Otherwise (ArrowRight on an expanded row or a row without children, ArrowLeft on a top-level row it can't collapse) the arrows move between cells as usual. In a right-to-left table the two arrows swap. Enter keeps its meaning: it fires `argus-cell-click`, as on any cell. A click on a toggle only expands or collapses its row: it fires no click events and selects nothing.

Screen readers hear each row's level, whether it's expanded, and its place among its siblings.

## Styling

The toggle is the `tree-toggle` part, drawn in the text colour (`currentColor`), and `--argus-tree-indent` (`1.25rem`) is the indent per level. While a filter keeps a row open, its toggle also has the `tree-toggle-disabled` part, dimmed by default:

```css
argus-table {
  --argus-tree-indent: 1.5rem;
}
argus-table::part(tree-toggle) {
  color: var(--accent);
}
argus-table::part(tree-toggle-disabled) {
  opacity: 0.6;
}
```

The toggle's accessible names, "Expand row" and "Collapse row", are the `expandTreeRow` and `collapseTreeRow` [labels](../labels/).

## Editing nested rows

With the [editing add-on](../editing/), `argus-cell-edit` carries the edited row's `depth`. A tree from `getParentId` has every row in `data`, so `applyEdit(data, detail, columns)` works as in any table. Nested children (`getSubRows`) aren't in `data`: give `applyEdit` a fourth argument with your `getSubRows` and a `setSubRows(row, children)` that returns a copy of the row with those children. It copies the rows on the path to the edited one and keeps the ids, so expanded and selected rows stay as they were.

```ts
table.addEventListener('argus-cell-edit', (event) => {
  table.data = applyEdit(table.data, event.detail, table.columns, {
    getSubRows: (entry) => entry.children,
    setSubRows: (entry, children) => ({ ...entry, children }),
  });
});
```

A formula's whole column (`[[size]]`, [formulas add-on](../formulas/)) holds every row the filters keep, child rows included, collapsed or not.

## Children from the server

When the rows come from a [`dataSource`](../infinite-loading/), their children can load as rows expand. Give the source two more members: `hasChildren(row)` says whether a row has children to load, so it gets a toggle (it's called for every loaded row: read a field), and `getChildren({ parent, parentId, sorting, filters, quickFilter, signal })` loads all of a row's children and resolves to `{ rows }`. Both are needed; with only one, the rows stay flat. `getRows` keeps returning the top-level rows, and children can have children of their own, loaded the same way.

```ts
const dataSource: DataSource<Folder> = {
  getRows: (request) => loadTopFolders(request), // the top-level rows, page by page
  hasChildren: (folder) => folder.hasChildren,
  async getChildren({ parentId, sorting, filters, quickFilter, signal }) {
    const query = new URLSearchParams({
      sort: JSON.stringify(sorting),
      filters: JSON.stringify(filters),
      q: quickFilter,
    });
    const response = await fetch(`/api/folders/${parentId}/children?${query}`, { signal });
    return { rows: (await response.json()) as Folder[] }; // [] removes the toggle
  },
};
```

Expanding a row calls `getChildren` once, with the current sort, filters and quick filter: return the children sorted like the rows, and those that match a filter or hold a match. Until the answer arrives, a loading row shows under the row. Children stay loaded, and collapsing keeps them, so a row opened again needs no request. A new source, sort, filters, quick filter or `getRowId`, or `refresh()`, drops them all (requests in flight are aborted through `signal`), and the expanded rows load their children again once their own rows have loaded; a `treeExpanded` restored with `setState()` opens the same way, as pages arrive.

When `getChildren` rejects, the loading row shows a Retry button instead (its name is the `retryChildren` [label](../labels/)), and the table fires `argus-load-error` with the row's id as `parentId`; its `start` is the row's index among the rows shown and `end` the next one. Retry, or expanding the row again, asks again.

Here a shared drive pages its 200 top-level entries from a pretend server that answers after a short delay; every project folder holds folders of its own. Expand one and its entries load. Sort by Name or Size: the open folders load their entries again, in the new order.

A child's id is `getRowId(row, index)` with its index among its siblings, or without `getRowId` its parent's id, a dot and that index (`'3.0'`, `'3.0.2'`), as for nested data. Give `getRowId` the server's ids, unique across levels, as the example does: an index changes when the server's answer does. `getRows`'s `start` and `end` and its `total` count top-level rows only; every other index counts the rows shown, top-level rows and the loaded children of expanded rows, as in any tree: `scrollToRow(index)`, the click events and `argus-range-change`.

The server filters, at every level. The table can't know which collapsed rows hold a match without loading their children, so a filter opens no rows here and disables no toggles: only `treeExpanded` opens rows, and the children of an expanded row load with the filters. With `selectBranches`, a tick reaches the loaded rows: a row whose children aren't loaded counts as a row without children, and children that arrive under a ticked row join the selection (with an `argus-selection-change`). While a filter or the quick filter is on, a parent's id is never selected, since the server may not have sent all of its children.

## Limits

- The first data column holds the toggle and the indent; there's no option to choose another one yet.
- With a [`dataSource`](../infinite-loading/), `getSubRows` and `getParentId` are ignored, with a warning in the console: children come from its `hasChildren` and `getChildren` ([above](#children-from-the-server)).
- A row's children load in one `getChildren` call: there are no pages of children.
- `scrollToRow({ id })` doesn't open a row's ancestors: for a row under a collapsed row it does nothing. Expand the ancestors through `treeExpanded` first.
- The [export add-on](../export/) exports the rows shown, without their levels. With a `dataSource` and `allRows`, it exports the top-level rows only, the rows `getRows` returns.
- `pinnedRows` have no tree.
