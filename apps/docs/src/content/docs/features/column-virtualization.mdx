Rows are always virtualized. With `virtualizeColumns` (`virtualize-columns`), columns are too: the scrolling columns in view render, plus two on each side, and pinned columns always render. Here 503 columns and 10,000 rows render a few hundred cells. Keyboard focus still reaches every column: End jumps to the last one, and the table scrolls it into view.

Turn it on for wide tables. Without it, every column renders in every row: 503 columns here would mean 12,000 cells, slow to scroll and, in Safari, slow to render at all.

Safari's cost grows with the square of the cells on screen. Each cell's content goes to a slot of its own, and WebKit assigns a slot more slowly the more slots a table has. Turning column virtualization off for this table, measured in Playwright's WebKit:

| Columns | Cells rendered | WebKit | Chromium |
| ------- | -------------- | ------ | -------- |
| 50      | 1,300          | 0.8 s  | 27 ms    |
| 100     | 2,500          | 2.4 s  | 45 ms    |
| 200     | 4,900          | 8.9 s  | 83 ms    |
| 500     | 12,000         | 56 s   | 0.2 s    |

So turn it on once a table has more than about 30 columns, or fewer on tall screens, where more rows are in view: what counts is the number of cells. Below that, rendering every column costs less than tracking which are in view. The details are in [issue #168](https://github.com/Joessst-Dev/argus-table/issues/168).
