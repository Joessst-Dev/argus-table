`selectionMode: 'multi'` (`selection-mode="multi"`): a click selects one row, Ctrl+click (Cmd+click on macOS) adds or removes a row, and Shift+click selects the range from the last row clicked. From the keyboard, Space toggles the focused row, Shift+ArrowUp/ArrowDown and Shift+PageUp/PageDown extend the selection from the last toggled row, and Ctrl+A (Cmd+A) selects every row. Selected rows get the `row-selected` part and `--argus-row-selected-bg`. `selection` holds their ids, from `getRowId`, and `argus-selection-change` reports each change.

## One row at a time

`selectionMode: 'single'` keeps one row selected. Ctrl+click or Space on the selected row clears it.

## Checkboxes

`selectionCheckboxes` adds a checkbox column, pinned first. A row's checkbox toggles that row and keeps the others; Shift+click adds the range from the last row clicked. The header's checkbox selects every row, shows a mixed state when some are selected, and clears the selection when all are. Space on a focused checkbox cell does the same as clicking its checkbox.

## Deciding what to allow

Set `selection` and the table is controlled: every change fires `argus-selection-change` with the proposed ids, and the table only changes once your code sets them. This one allows at most five rows: Shift+click a range of ten and nothing changes. Bind `selection` one way for this (not `v-model:selection` or `[(selection)]`, which apply every proposal).

With a [`dataSource`](../infinite-loading/), only loaded rows can be selected: skeleton rows can't, and Ctrl+A selects the rows loaded so far. `selection` keeps its ids while pages are evicted and loaded again.

In a [tree of rows](../tree-rows/#selecting-branches), `selectBranches` makes ticking a row tick its whole branch, with part-ticked checkboxes on rows whose branch is partly selected.
