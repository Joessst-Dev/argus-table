# Accessibility and keyboard

[← Back to contents](../README.md)

The table follows the WAI-ARIA grid pattern from the first release; retrofitting it later would mean rewriting focus handling.

- Roles: `grid`, `rowgroup`, `row`, `columnheader`, `gridcell`. The host is the grid: ElementInternals sets the role, and the element also adds a `role="grid"` attribute when it connects (unless the page set a role), because axe-core and similar tools don't read ElementInternals. Also: `aria-rowcount` / `aria-colcount` for the full size and `aria-rowindex` / `aria-colindex` on rendered rows and cells, so virtualization stays invisible to screen readers.
- Sorting announced via `aria-sort` on the sorted header only (none on the others, as the APG recommends). Sortable headers sort with Enter or Space when focused. Enter on a focused body cell fires `argus-cell-click` and `argus-row-click`, as a click does.
- One tab stop into the grid, then roving focus: arrows move by cell (Left/Right mirrored in RTL) and between the header row and the body, Home/End by row. Ctrl+Home goes to the first header and scrolls to the top; Ctrl+End goes to the last row's last cell (Cmd also works, for macOS). PageDown and PageUp move by the number of whole rows that fit below the header, keep the column, and scroll the view by as many rows, so the focused cell keeps its place on screen. PageDown from the header lands a page into the body; PageUp stops at the first body row (ArrowUp goes on to the header). Rows from `pinnedRows` are rows of the grid like any other: ArrowUp and ArrowDown move header → top pinned rows → body → bottom pinned rows, and Ctrl+End lands on the last pinned row (scrolling the body to its end). PageUp and PageDown page through the body only, by the whole rows that fit between the header and pinned rows, and move from a pinned row into the body; a body row focused from the keyboard scrolls clear of the pinned rows. With a `selectionMode`, Space (or Shift+Space) on a body cell toggles its row; in `multi` mode Shift+ArrowUp/ArrowDown and Shift+PageUp/PageDown move focus through the body and select from the anchor (the last row toggled or clicked) to the focused row, and Ctrl+A (Cmd+A) selects every row. Shift+Arrow stops at the body's ends: the header and pinned rows can't be selected. Selectable rows carry `aria-selected` (`true` or `false`), and the grid is `aria-multiselectable` in `multi` mode. The checkbox column (`selection-checkboxes`) is a column of the grid like any other: its checkboxes are labelled "Select row" and "Select all rows" (English until the table gets an i18n option) but aren't focusable, so focus stays on the roving cell; Space on a checkbox cell, or on the select-all header, does what its checkbox does. The tab stop starts on the first header. Keys pressed inside cell content (an input, a button) are left to that content.
- Focus survives virtualization: the focused cell is tracked by row id + column id and kept rendered, holding its row-pool slot so its DOM is never recycled.
- Body rows are pooled and stay in pool order, so DOM order can differ from visual order. Keeping the DOM sorted cost too much (the ADR 0001 [addendum](../../adr/0001-shadow-vs-light-dom.md#addendum-sorted-dom-phase-1)), so row positions come from `aria-rowindex` alone, and keyboard navigation moves by row index, never by DOM sibling. The v0.1 screen-reader check confirmed this with VoiceOver and Safari; NVDA with Firefox was skipped and is still to do (ADR 0001).
- Resize handles reachable by keyboard (focus header, then Alt+Arrow to resize), with `aria-valuenow`.
- Columns move by keyboard too: Alt+Shift+Arrow on a focused header moves it one place within its pin group (mirrored in RTL). Focus stays on the moved header, and a polite live region in the document body (outside the grid, which may only own rows) announces the new position: "Customer moved to column 3 of 8".
- The column menu add-on (`@argus-table/header-menu`) follows the menu button pattern without adding a tab stop: its button in each header has `tabindex="-1"`, `aria-haspopup="menu"`, `aria-expanded` and the label "Column menu". Alt+ArrowDown on a focused header opens the menu, and so do the context menu key, Shift+F10 and a right-click. The menu is a `role="menu"` popover labelled by the column's header, with `menuitemradio` items for the sort and the pin (`aria-checked`) and `menuitem`s to fit the width, hide the column and show hidden ones (in a labelled group). Opening it focuses the checked sort item, else the first. ArrowUp and ArrowDown move and wrap, Home and End jump, Enter or Space runs an item, and Escape or Tab closes it; focus then returns to the header. Fitting, pinning, hiding and showing a column are announced through the live region ("Total fitted to 96 px", "Total pinned to the end", "Total hidden"). Hiding a column moves focus to the header that takes its place. Plugins see keys on a focused header or cell before the table (the `keydown` hook) and can claim them.
- Formula columns (`@argus-table/formulas`): the `ƒx` mark before a formula header is `aria-hidden`, so the header reads as its text. An error cell reads its code (`#DIV/0!`); the explanation is in a `title` tooltip, which screen readers may or may not announce and keyboard users can't open; the editor (below) shows it in full.
- The formula editor is a native modal `<dialog>` (focus stays inside, Escape closes it, the page behind is inert) labelled by its heading. Fields have visible labels; a problem sets `aria-invalid` and is tied to its field with `aria-describedby`, as is the argument hint. The formula field is an ARIA combobox (`aria-autocomplete="list"`, `aria-expanded`, `aria-activedescendant`) over a `role="listbox"` of suggestions: ArrowUp/ArrowDown move, Enter or Tab takes one, Escape closes the list before the dialog, Alt+ArrowDown opens it. The coloured copy of the formula behind the input is `aria-hidden`; in forced-colors mode it's hidden and the input shows its own text. The preview is a `<table>` labelled by its heading. On close, focus returns to the header the editor opened from (after a delete, to the next header), and adding, changing or deleting a column is announced through the live region.
- The column menu groups other plugins' items in labelled `role="group"`s; an item's dimmed detail (a formula) is part of its name.
- Visible focus ring via `--argus-focus-ring`; every theme must pass WCAG AA contrast.
- `prefers-reduced-motion` turns off smooth scrolling and transitions.
- Automated axe checks in CI, plus a manual screen-reader pass (NVDA, VoiceOver) before each minor release, following the [screen-reader check](../../a11y/screen-reader-check.md).
