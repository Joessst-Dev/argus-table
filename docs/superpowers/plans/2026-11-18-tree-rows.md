# Tree rows, step 1 (client-side trees): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rows can have child rows, from nested (`getSubRows`) or flat (`getParentId`) data held in memory: indented under their parent in the first data column, expanded and collapsed with a toggle or Right/Left, sorted within siblings, filtered with their ancestors kept, selectable row by row or by branch.

**Architecture:** Approach A of the spec. Core builds a `RowTree` once per data identity (every row by _source index_, its id, parent and depth). `RowPipeline` gets three tree steps that replace the flat ones when a tree is configured: keep matches with their ancestors, lay the kept rows out depth-first with siblings in sort order (one global `sortRows` call, then bucketing by parent, so radix sorting and one sort function per column still hold), and drop rows under collapsed parents. `rows()` stays "source indexes in the current order", so `DisplayRows`, positions, selection, events and plugins keep working on child rows. The element adds the properties, the toggle and indent in the tree column's cells, treegrid ARIA, the keys, and branch selection.

**Tech Stack:** Lit 3, TypeScript (strict, `noUncheckedIndexedAccess`, `.js` imports), core's own row model (ADR 0010), Vitest (Node for core, browser mode for the table), Playwright, Storybook, Astro docs site, Nx, Changesets.

**Spec:** `docs/superpowers/specs/2026-11-18-tree-rows-design.md` (read it with this plan: it holds the behaviour, the anti-goals and the calls already made). Step 2 (`DataSource.getChildren`) is **not** in this plan.

**Branch:** `feat/tree-rows` (the spec is its first commit). One PR into `main`.

**Where to run things:** the mounted repo's `node_modules` hold macOS binaries; run installs, builds and tests in the Linux scratchpad copy (`sync.sh`, then `env.sh`), never `pnpm install` in the mount. Commands below are the repo's own (`CLAUDE.md`, "Commands").

## Global Constraints

- Public names, exactly: properties `getSubRows` (`(row: T) => readonly T[] | undefined`), `getParentId` (`(row: T) => string | null | undefined`), `treeExpanded` (`TreeExpandedState = readonly string[]`, controllable), `selectBranches` (boolean, attribute `select-branches`, default `false`); event `argus-tree-expanded-change` with `detail: { treeExpanded, rowId, open }` (`TreeExpandedChangeDetail`); `TableState.treeExpanded`; optional `depth` on `CellContext`, `CellClickDetail`, `RowDetailContext`; part `tree-toggle`; token `--argus-tree-indent` (default `1.25rem`); labels `expandTreeRow` = `'Expand row'`, `collapseTreeRow` = `'Collapse row'` (German `'Zeile aufklappen'`, `'Zeile zuklappen'`); `PluginHost.rowDepth(index, section?)` and `PluginHost.sourceRow(index)`.
- `expanded` / `argus-expanded-change` keep meaning detail panels. Nothing frozen changes (ADR 0004: additions only).
- Every public index stays an index in the current order, which is now the rows **shown** (children of collapsed rows are out of it, like filtered-out rows).
- Source indexes: top-level and flat rows keep their index in `data`; nested children get `data.length` onwards in depth-first preorder. `getRowId(row, index)`, `accessor(row, index)`, `readValue` and `filteredIndexes()` use source indexes.
- Default ids: top-level `String(index)` (unchanged); nested children `` `${parentId}.${indexAmongSiblings}` `` (`'3.0'`, `'3.0.2'`), unless `getRowId` is set.
- Without `getSubRows` and `getParentId` (or with a `dataSource`, step 1), no tree: every new step is the identity and allocates nothing.
- Both functions set: `getSubRows` wins, one `console.warn`. Missing parent or a cycle (flat data): the row is top-level, one `console.warn` per tree build.
- No hard-coded user-visible text; new labels in `TableLabels` with JSDoc and German text in the Features/Labels story (`satisfies` makes the typecheck enforce it).
- New controllable state follows `controllable()` and `StateEvents.change()`; `TREE_EXPANDED_CHANGE` goes into `StateEvents`' order list after `EXPANDED_CHANGE`.
- `@cssprop`, `@csspart`, `@fires` JSDoc on `ArgusTable` for the new token, part and event; property JSDoc for each property (feeds the manifest and the wrappers).
- The toggle's click handler never calls `preventDefault()`; the toggle has `tabindex="-1"` (one roving tab stop).
- CDN budget is 47 kB (`packages/table/.size-limit.json`); the PR states the new size and raises the limit only with the owner's approval (estimate +2–3 kB). formulas has ~40 B headroom: check it.
- A changeset per published package changed, written for users (`argus-table` minor, `@argus-table/editing` minor, `@argus-table/formulas` patch, the three wrappers minor).

## Review Focus

1. **A filter whose only match is a deep child under collapsed rows:** the match shows in place, its ancestors show open with `aria-expanded="true"`, `treeExpanded` is unchanged, and clearing the filter collapses them again. Test in task 3.
2. **A click on the tree toggle:** it toggles only; no `argus-cell-click` / `argus-row-click`, no selection change, focus lands on the toggle's cell. Test in task 6.
3. **Collapsing a row while the active cell is on one of its descendants**, by key, by click, and by a controlled host setting `treeExpanded`: the active cell moves to the collapsed row in the same column, and focus isn't lost. Test in task 7.
4. **A new `data` array after an edit (`applyEdit`), with default ids:** expanded rows stay expanded, selection stays, measured heights follow ids. Test in task 3 (core) and task 9 (editing).
5. **A row whose `getSubRows` returns `[]` or `undefined`, or whose children are all filtered out:** no toggle, no `aria-expanded`, Right moves right as on any cell. Test in task 2 (core) and task 6 (render).

  export interface TreeSource<TData> {
    getSubRows?: ((row: TData) => readonly TData[] | undefined) | undefined;
    getParentId?: ((row: TData) => string | null | undefined) | undefined;
  }
  /** Every row of a tree by source index. */
  export interface RowTree<TData> {
    readonly rows: readonly TData[]; // by source index; rows[i] === data[i] for i < data.length
    readonly ids: readonly string[]; // by source index
    readonly parent: Int32Array; // source index of the parent, -1 for top-level
    readonly depth: Int32Array; // 0 for top-level
    readonly childCount: Int32Array; // children in the tree (filters not applied)

    data: readonly TData[],
    source: TreeSource<TData>,
    getRowId: ((row: TData, index: number) => string) | undefined,
    warn?: (message: string) => void, // default console.warn

### Task 2: The tree steps: keep ancestors, lay out sorted siblings, drop collapsed rows

**Files:**

- Create: `packages/core/src/table/tree-order.ts`
- Test: `packages/core/src/table/tree-order.test.ts`

**Interfaces:**

- Consumes: `RowTree` (task 1).
- Produces:

  ```ts
  export interface KeptRows {
    rows: readonly number[]; // source indexes the filters keep, ascending
    /** Rows kept because a descendant matches (1) while a filter is on; undefined without one. */
    holdsMatch: Uint8Array | undefined;
  }
  export function keepWithAncestors<TData>(
    tree: RowTree<TData>,
    test: ((row: TData, index: number) => boolean) | undefined,
  ): KeptRows;

  export interface TreeLayout {
    /** Kept rows depth-first, each sibling group in the order of `sorted`. */
    readonly order: Int32Array;
    /** Kept children per source index (0 for rows not kept). */
    readonly keptChildren: Int32Array;
    /** 1-based position among kept siblings, per source index. */
    readonly posInSet: Int32Array;
    /** Kept children of a row in layout order; `-1` for the kept top-level rows. */
    children(parent: number): Int32Array;
  }
  export function layoutTree<TData>(tree: RowTree<TData>, sorted: readonly number[]): TreeLayout;

  /** The rows of `layout.order` whose ancestors are all open. */
  export function showOpen<TData>(
    tree: RowTree<TData>,
    layout: TreeLayout,
    isOpen: (index: number) => boolean,
  ): number[];
  ```

- [ ] **Step 1: Write the failing tests** (Node), on a fixture tree `A{A1{A1a}, A2}, B{B1}` (source indexes from task 1):
  - `keeps a match's ancestors but not its descendants` — test matching `A1` only → `rows` = A, A1 (not A1a, A2, B, B1); `holdsMatch[A] === 1`, `holdsMatch[A1] === 0`.
  - `without a test every row is kept and holdsMatch is undefined`.
  - `lays out siblings in sorted order, children under their parent` — `sorted` = all kept rows in the order B1, A2, B, A1a, A1, A → `order` = B, B1, A, A2, A1, A1a; `posInSet[A2] === 1`, `posInSet[A1] === 2`; `keptChildren[A] === 2`; `children(-1)` = [B, A].
  - `drops rows under collapsed parents` — `isOpen` true for A only → B, A, A2, A1 (A1 closed hides A1a; B closed hides B1).
  - `a row with no kept children is a leaf` — after a filter keeping A and A1 only (match on A1), `keptChildren[A1] === 0` (A1a filtered out).
  - `empty getSubRows results are leaves` — `getSubRows: () => []` → `childCount` and `keptChildren` 0 everywhere.
  - `stays linear at a million rows` — 100k parents × 9 children: `keepWithAncestors` + `layoutTree` + `showOpen` finish in under 1 s in Node (a guard against quadratic code, not the performance target).

- [ ] **Step 2: Run them to see them fail**
      Run: `pnpm --filter @argus-table/core exec vitest run src/table/tree-order.test.ts`
      Expected: FAIL, cannot find `./tree-order.js`.

- [ ] **Step 3: Implement the three functions in `tree-order.ts`.** `keepWithAncestors`: mark each match, then walk up parents until a marked row (amortized O(n)), marking ancestors in `holdsMatch`. `layoutTree`: count kept children per parent (roots under a virtual parent), prefix sums into `childStart`, fill `children` by iterating `sorted` (so each group is in sort order and `posInSet` falls out), then a preorder walk with an explicit stack into `order`. `showOpen`: walk `order`; on a closed row with kept children, skip the following rows while their depth is greater.

## Calls made in this plan (to check)

- **Enter on a tree cell keeps today's meaning** (a click: `argus-cell-click`; the editing add-on still takes it first on editable cells). Toggling is by the toggle, Right and Left. The spec left this to the builder; Enter toggling would change what apps already get on Enter in their first column.
- **Toggle labels are new keys**, `expandTreeRow` / `collapseTreeRow` (`'Expand row'` / `'Collapse row'`), because `expandRow` / `collapseRow` already say "Show details" / "Hide details". Like the detail chevron, the name changes with the state and `aria-expanded` is set too.
- **The indent is an element in the cell's shadow content** sized by `--argus-tree-indent`; the token is the one documented way to restyle it (no `tree-indent` part).
- **Trees with a `dataSource` are ignored in step 1**, with a console warning; step 2 adds them.
- **`selectBranches` applies in `'multi'` mode only.**
- **`depth` is set only when a tree is configured**, so contexts without a tree are exactly as today.
- **A row is a parent only if it has children the filters keep**: a parent whose children are all filtered out shows no toggle while the filter is on.
- **`nextTreeExpanded` accepts any row with children in the tree** (filters not applied), so a controlled host's ids are never rejected for a filter.
- **A tree row's toggle click fires no cell or row click**, like the checkbox and chevron columns' controls.
- **Sorting a tree is one global sort plus a bucketing pass**, so each column's sort function is picked once (not per sibling group) and radix sorting still applies.
