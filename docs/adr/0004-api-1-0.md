# ADR 0004: The 1.0 API review

- **Status:** Accepted (12 November 2026).
- **Applies to:** every published package: `argus-table`, `@argus-table/react`, `vue`, `angular`, `header-menu`, `formulas` and `themes`.

## Context

1.0 freezes parts, tokens, events and properties ([Roadmap](../plan/plan/12-roadmap.md)). Every feature Phase 3 named has shipped, and they were added one at a time over three releases. Before the freeze, the element, the public types, the plugin API, the wrappers, the themes and the add-ons were surveyed for names and shapes that are hard to change later. The findings fall into three kinds:

- **Inconsistent names for the same idea.** State events follow three patterns (`argus-sort-change`, `argus-column-resize`, `argus-row-select`), and their detail keys differ from the property names (`sizing` against `columnSizing`). "Cleared" is `null` in `setSort`, `false` in `setPin` and `undefined` in `setFilter`. A sort direction is written four ways.
- **Names that mislead.** `virtualize-columns="false"` turns the feature on, while `sortable="false"` on a column turns sorting off. `--argus-outline` sets a border. The part `cell-pinned-row` sits next to `cell-pinned`, which means a pinned _column_.
- **Gaps.** The sort direction and the headers of pinned columns can't be styled. The themes don't set the add-ons' tokens. In React and Vue, the plugin hooks are typed with the table's content type.

Each fix is breaking. After 1.0 it would need a major release; before 1.0 it costs a migration note in a changelog.

## Decision

The breaking changes ship together in 0.4, the release candidate for 1.0. Changes that only add to the API wait until after 1.0, since adding is allowed in minor releases. Each change has a changeset written from the user's side, with the old name → new name.

### Events: `argus-<property>-change`

An event that reports a change of controllable state is named after the property, and its `detail` holds the new value under the property's name, followed by the cause:

| Before                 | After                            | `detail`                                    |
| ---------------------- | -------------------------------- | ------------------------------------------- |
| `argus-sort-change`    | `argus-sorting-change`           | `{ sorting }`                               |
| `argus-column-resize`  | `argus-column-sizing-change`     | `{ columnSizing, columnId, width }`         |
| `argus-column-reorder` | `argus-column-order-change`      | `{ columnOrder, columnId, groupId? }`       |
| `argus-column-pin`     | `argus-column-pinning-change`    | `{ columnPinning, columnId, pin }`          |
| `argus-column-hide`    | `argus-column-visibility-change` | `{ columnVisibility, columnId, visible }`   |
| `argus-column-filter`  | `argus-column-filters-change`    | `{ columnFilters, columnId, columnFilter }` |
| `argus-row-select`     | `argus-selection-change`         | `{ selection }`                             |

- `visible` has the same polarity as `columnVisibility`, where `true` means shown. The old `hidden` field had the opposite one.
- Some of the old names hid half of what they report: `argus-column-hide` also fired when a column was shown, `argus-column-pin` when one was unpinned and `argus-column-filter` when a filter was cleared.
- **The event is the two-way update.** The wrapper generator derives two-way binding from this convention (property `p` ↔ event `argus-<kebab(p)>-change`, detail key `p`) instead of a hand-kept list:
  - Angular gets one output, `pChange`, which emits the value, so `[(columnSizing)]` works. The full detail is available through the native `(argus-column-sizing-change)` binding.
  - Vue emits `update:p` and `p-change` (the latter with the detail).
  - React gets `onPChange`.
- The old names existed only because `argus-selection-change` would have collided with Angular's `selectionChange` of `[(selection)]`. With one output per property, that collision no longer arises.
- **Timing is unchanged, and documented in each `@fires`.** A controlled change fires synchronously with the _proposed_ value. An uncontrolled change fires after the update that applied it. `argus-column-sizing-change` still fires on every frame of a drag, because controlled resizing has to follow the pointer.
- **Events that don't report state keep their names.** `argus-row-click`, `argus-cell-click`, `argus-range-change` and `argus-load-error` stay as they are.
  - `argus-cell-click` gains `rowId` and `index`, like `argus-row-click`.
  - `argus-range-change` becomes `{ first, last }` (both inclusive) instead of `{ start, end }`. Everywhere else, `end` is exclusive (`RowsRequest`, `LoadErrorDetail`, like `Array.prototype.slice`). Renaming the fields turns old code into a type error instead of a silent off-by-one.
  - The formula events (`argus-formula-column-add`, `-change`, `-remove`) report actions the app applies, not state, and keep their names.
- **Detail types and the exported event-name constants are renamed to match:** `SortingChangeDetail`, `ColumnSizingChangeDetail`, and so on.

### Attributes and properties

- **`"false"` means off on every element.**
  - Today, `virtualize-columns` and `selection-checkboxes` use Lit's `type: Boolean`, where any value, `"false"` included, means on.
  - They change to the converter the column flags use. With it, an absent attribute means the default, `"false"` means off and any other value means on.
  - True HTML booleans with negated names (`no-sort`) were the alternative. They were not chosen because the column flags (`sortable`, `resizable`, `reorderable`, `pinnable`, `hideable`) default to `true`, and their names read better than negations.
- **Kept, and documented as final:**
  - `getRowId`: TanStack's and AG Grid's name for it.
  - `accessor`.
  - `selectionCheckboxes`.
  - `quickFilter` as a plain property with no change event: the app owns the search box.
  - `contentRenderer` as public API for framework integrations.
- **`toColumnDef()`, `toColumnGroup()` and `flagConverter` are `@internal`.** They serve the table and are left out of the wrappers.
- **`undefined` and `false`.** `undefined` means "no value". `false` means "explicitly off, overriding the column definition" and is used only by pinning and visibility, where `columnPinning: { id: false }` unpins a column that `ColumnDef.pin` pins. This rule changes `PluginHost.setSort(id, direction)`: clearing the sort now takes `undefined` instead of `null`.
- **Sort direction.** A new exported type, `SortDirection` (`'asc' | 'desc'`), is used by `ColumnInfo.sorted` and `setSort`. `SortItem.desc` stays, because saved state holds it.
- **Filters.** `ColumnDef.filter` keeps meaning the _kind_ of filter, alongside `sortable` and `pin`. Wherever a filter _value_ appears, it is called `columnFilter`: in the event detail, and in `ColumnInfo` (formerly `filterValue`, which clashed with the type `FilterValue`).
- **Sorting by several columns.** `sorting` takes several items, applied in order. A header click replaces the order with that one column. Multi-sort is something a host or plugin sets.

### Types and the plugin API

- **Every `PluginHost` member is required.** The table provides all of them. The "optional, like any later addition" members (`columns`, `setPin`, `setHidden`, `setFilter`, `filterValues`, `filteredIndexes`, `row`, `content`) made plugins check for each one. Plugins receive a `PluginHost`; they never implement one. So a member added after 1.0 can be required too, and adding it is not a breaking change. `ColumnInfo.filter` and `columnFilter` become required too.
- **The plugin hooks see content as `unknown`.** `columns(defs)` and `columnGroups(groups)` take `ColumnDef<T, unknown>` and `ColumnGroup<unknown>`. A React or Vue table hands plugins its own content, and the hooks were typed as if it were `CellContent`. Plugins pass content they don't own through `host.content()`.
- **Other plugin-hook types:**
  - `willUpdate`'s `changed` is a `ReadonlySet<string>` of property names.
  - `columns` and `columnGroups` may return `undefined`, meaning "unchanged", which the runtime already accepts.
- **State arrays are `readonly`:** `SortState`, `ColumnOrderState`, `SelectionState` and `SetFilter.values`, like the properties that take them.
- **Saved state:**
  - `TableState` gains `version: 1`. `getState()` writes it, and `setState()` ignores state with another version. A saved layout can then be migrated after 1.0.
  - `ScrollState.left` becomes `inline`: it is a logical offset from the start edge, positive in RTL too.
- **Wrappers:** the list of type re-exports is the same in React, Vue and Angular. It is checked by `lint` instead of copied by hand three times.
- **Add-ons:** formulas exports the type of its menu items and constants for its event names.

### Tokens and parts

- **Renamed tokens:**

  | Before                                                   | After                   | Why                                                                                                                   |
  | -------------------------------------------------------- | ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
  | `--argus-pinned-row-bg`                                  | `--argus-row-pinned-bg` | Every row background is `--argus-row-*-bg`. "pinned" alone also reads as the pinned columns (`--argus-pinned-shadow`) |
  | `--argus-row-stripe-bg`                                  | `--argus-row-odd-bg`    | It colours the part `row-odd`                                                                                         |
  | `--argus-outline`                                        | `--argus-border`        | It sets a `border`; the outline is `--argus-focus-ring`                                                               |
  | `--argus-radius`                                         | `--argus-border-radius` | Next to `--argus-border-width` and `--argus-border-color`                                                             |
  | `--argus-formula-{error,function,ref,number,text}-color` | `--argus-formula-…-fg`  | Text colours are `-fg` everywhere else (`--argus-fg`, `--argus-header-fg`, `--argus-menu-fg`)                         |

- **`--argus-dialog-*` stays.** It is the family for dialogs that add-ons open, as `--argus-menu-*` is for their menus. Both are listed with the table's tokens.
- **Parts:**
  - `cell-pinned-row` → `cell-in-pinned-row`. `cell-pinned` stays for cells in a pinned _column_.
  - New parts:
    - `header-cell-pinned` and `header-cell-pinned-edge`, like the body cells.
    - `header-cell-sorted-asc` and `header-cell-sorted-desc`. `::part()` can't read `aria-sort`.
    - `sort-indicator`: today the class `.sort-indicator`.
    - `row-error`: a row whose page failed. Today it is only `row-loading` with `skeleton-error`.
- **Add-on fallbacks.** Each add-on uses one fallback per token. Today, `--argus-border-color` falls back to four different mixes across the column menu and the formula editor.
- **Themes.** The five themes set the add-ons' tokens too, so the column menu and the formula editor take on the theme. A test checks that every token a theme sets is read by the table or an add-on, and that every part a theme styles exists.
- **Release.** `@argus-table/themes` joins the changesets `fixed` group: a token rename changes the table and the themes together.

### Compatibility policy from 1.0

- **Breaking, so only in major releases:**
  - renaming or removing a property, attribute, method, event, `detail` field, part, token or slot;
  - changing what a value means;
  - making an input type narrower.
- **Not breaking:**
  - **New members in union types the table outputs** (`CellTarget.section`, `FilterKind`, `ColumnFilter`, `SelectionMode`). Code that switches over them needs a default branch.
  - **New `PluginHost` members** and new optional plugin hooks.
  - **New optional fields** in definitions, details and `TableState`.
  - **Different text in the default English strings and announcements.**
- **The look is not frozen.** The default theme's values (colours, spacing) may change in minor releases. The names of tokens and parts may not.

## Options not taken

- **Keep the event names and only rename the detail keys.** A smaller break, but Angular would keep two outputs per state (`sortChange` beside `sortingChange`), and the names would stay in three patterns.
- **Ship deprecated aliases** (both event names, both token names) through 1.x. Firing every state event twice, and reading two tokens with nested `var()` fallbacks, costs bytes and confuses the docs. The project is pre-1.0 and has few users, so a release with migration notes is cheaper for them too.
- **Open union types** (`FilterKind | (string & {})`) for custom filter kinds. Without a way to register a kind, a `dataSource` and the column menu couldn't do anything with one. `filterFn` covers custom tests, and the policy above lets the unions grow.
- **Move `ColumnDef.formula` into the formulas package**, through module augmentation. That is cleaner, but `<argus-column formula>` has to be read by the element. A generic `meta` field for plugins can be added after 1.0 without breaking anything.

## After 1.0 (additions, in no order)

- Localizable strings for the built-in text ("Retry", "Select row", "Resize column", the announcements). Done: `labels` ([ADR 0005](0005-labels.md)).
- `scrollToColumn(id)` and options for `scrollToRow()`, such as alignment and scrolling by row id. Done: `scrollToRow(target, { align })` with `target` an index or `{ id }`, and `scrollToColumn(id, { align })`; both resolve `true` when the target is in view.
- A `HeaderContext` argument for `header()`, so plugins can label any header.
- `ColumnDef.meta` for plugins' own fields.
- A reflected `selection-mode` attribute. Done: it reflects like `density`, with `none` as the default.
- A "resize finished" signal for persisting widths. Done: `argus-column-resize-end` with `{ columnSizing, columnIds }`, once per drag, key press or fit.
- The formula events in the wrappers. Done: `onFormulaColumnAdd` / `@formula-column-add` / `(formulaColumnAdd)` and the same for change and remove, from the generator's list of add-on events, with detail types each wrapper writes with its own columns.
- Options in the column menu to turn off its sort and fit-width items. Done: `headerMenu({ sort: false, fitWidth: false })`.
- Passing a formula's syntax tree to `getRows` so formula columns can sort and filter with a `dataSource`.

## Consequences

- 0.4 breaks every app that listens to a state event or sets a renamed token, part or attribute value. The changelog entries list each rename, and the themes, starters, stories and docs move with it.
- The wrapper generator no longer keeps a list of two-way properties: a new controllable state gets two-way binding by following the naming convention.
- The roadmap's 1.0 gate becomes: 0.4 has been out long enough for feedback, and nothing in this record is still open.
- 1.0.0 was released on 12 November 2026, the day 0.4 and 0.5 came out. The changes in this record had all shipped; the feedback period was waived by the maintainer, so feedback on 1.0 goes into 1.x additions or a 2.0.
