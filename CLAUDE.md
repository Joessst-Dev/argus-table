# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`<argus-table>`: a framework-agnostic, virtualized data table web component built with Lit 3, TanStack Table v9 (`@tanstack/table-core`) and TanStack Virtual. pnpm + Nx monorepo, Node ≥ 22.12 (`.nvmrc`), pnpm via Corepack. Currently 1.0: the public API (properties, events, parts, tokens, slots) is frozen under ADR 0004's compatibility policy, so a breaking change needs a major release. Built up as v0.1 (virtualized rows, pinned columns, sorting, resizing, keyboard nav, default theme) plus, for v0.2, `dataSource` infinite loading, pinned rows, auto column widths, column reordering, `<argus-column>` children, the React, Vue and Angular wrappers, the Material-inspired theme, the benchmarks (Storybook "Benchmarks" page, fed by `benchmarks/published/`), scroll scaling past the engines' maximum element height and the StackBlitz starters (`apps/examples`). Phase 3 has started: row selection (`selectionMode`, `selection`), column virtualization (`virtualizeColumns`), column pinning and visibility as state (`columnPinning`, `columnVisibility`), filtering (`columnFilters`, `quickFilter`), column groups (`columnGroups`, `<argus-column-group>`), wrapped cell text (`ColumnDef.wrap`), measured row heights (`rowHeight: 'auto'`), the Fluent-inspired, Bootstrap-inspired and minimal themes, and plugin hooks (`plugins`) with the column menu add-on `@argus-table/header-menu`, formula columns with their editor (`@argus-table/formulas`), and saved state (`getState()` / `setState()`). After 1.0 (ADR 0004's additions): translatable built-in text (`labels`, ADR 0005), `scrollToColumn()` and `scrollToRow()` with `align` and row ids.

`docs/plan/` is the design plan (public API draft, roadmap, architecture diagrams). It describes intended features too, so check the source before assuming something exists (for example the plugin `state` hook is described but not implemented). `docs/adr/0001-shadow-vs-light-dom.md` explains the rendering model below.

## Packages

- `packages/core` (`@argus-table/core`, **private, never published**): DOM-free logic, tests run in Node. Column resolution, the TanStack adapter (`table/create-table.ts`), the `controllable` state helper, the `RowPool`. It is bundled into `argus-table`'s build; `packages/table/scripts/check-dist.mjs` fails the build if any `dist` file still imports it. A core change ships as an `argus-table` changeset.
- `packages/table` (`argus-table`, published): the Lit element. Build = Vite library build (ESM, `preserveModules`, lit/TanStack external) + CDN build with everything inlined (`vite.cdn.config.ts`) + bundled `.d.ts` (rollup-plugin-dts) + Custom Elements Manifest (`cem analyze`, from JSDoc on the class) + publint/attw.
- `packages/react` (`@argus-table/react`, published): `@lit/react` components for both elements; the table is wrapped in `withContent()` (`src/content.tsx`: a `ContentRenderer` that renders JSX from `cell`/`header` through portals, committed with `flushSync`; `react-dom` is a peer). `src/generated/elements.ts` is generated and committed: after a change to the element's properties or `@fires` tags, build `argus-table` and run `pnpm --filter @argus-table/react generate` (`lint` fails on a stale file). The generic signatures and type re-exports in `src/index.ts` are hand-written. In the versioning `fixed` group with `argus-table`.
- `packages/vue` (`@argus-table/vue`, published): same layout and `generate` script as React. Content (`src/content.ts`, `define.ts` for a spec with `content: true`): a `ContentRenderer` that renders VNodes with Vue's `render()` (synchronous) and an `appContext` whose `provides` are the wrapper instance's, so cells see the app and the table's ancestors' injections; `#cell-<id>` / `#header-<id>` slots become `cell`/`header`, and `#group-<id>` a column group's `header`, through an internal first plugin (`vue-slots`, prepended to `plugins`), each rendering through `ArgusSlot` so a slot tracks the parent state it reads. The generated file is a description of each element plus types in vue-tsc's generic-component shape; `src/define.ts` turns a description into a component (sets element properties itself, emits events and `update:*`, exposes methods). Typecheck is `vue-tsc`, and the tests mount SFCs (`src/test/Declarative.vue` also holds `@vue-expect-error` type checks).
- `packages/angular` (`@argus-table/angular`, published): standalone components on the element tags, generated with `@Input()` setters and `@Output()`s (not `input()`/`output()`: the tests run TestBed in JIT mode in Vitest, which can't see signal inputs without the CLI's transform; for the same reason test hosts use `@ViewChild`). `src/set-property.ts` routes strings to attributes. Built by ng-packagr; `typecheck` also runs `ngc` on `src/test/types.ts` with strict templates. Test mounts call `fixture.detectChanges()` right away so bindings land before the elements' first update; test hosts hold state in signals (zoneless). Content (`src/content.ts`): the generated `ArgusTableComponent` extends `ArgusTableBase`, which sets a `ContentRenderer` for templates (CDK-portal style: an embedded view in the component's `ViewContainerRef`, its nodes moved into the target, `detectChanges()` synchronously; a reused target gets `Object.assign` on its context), queries `ArgusCellDirective` / `ArgusHeaderDirective` / `ArgusGroupHeaderDirective` (`ng-template[argusCell]`, `[argusHeader]`, `[argusGroupHeader]`) and maps them to `cell`/`header` and groups' `header` through an internal first plugin (`angular-templates`; the generated `plugins` input calls `setPlugins`). `argusTemplate()` is the foreign value `cell` functions return.
- `packages/header-menu` (`@argus-table/header-menu`, published): the column menu, a plugin (see Plugins below). It imports only types from `argus-table` (a peer, with `lit`), so it never registers a second element. Its `columns` hook wraps each header in a function that renders the original content, a menu button and, while open, a `popover="auto"` `role="menu"` inside the header's light-DOM content (in the flat tree, so it inherits the table's tokens; in the top layer, so nothing clips it); it's placed with `position: fixed` from the button's rect each frame while open. Per-table state lives in a `WeakMap` keyed by the element, so one plugin instance can serve several tables. Its CSS is a constructable sheet adopted into the table's root node (`@layer argus-header-menu`). Its own items: sort, filter (Filter… opens `filter-form.ts`, a `popover="auto"` `role="dialog"` in the same header content, through `host.setFilter` / `host.filterValues`; typed values apply after 250 ms), pin (`host.setPin`), fit width, hide (`host.setHidden`) and a "Hidden columns" group (`host.columns()`); `headerMenu({ sort, fitWidth, pin, hide, filter })` turns those items off (`hasMenu` uses the same checks, so a column with nothing left gets no button), and labels for hidden columns come from the text headers its `columns` hook saw. Other plugins add menu items with a `headerMenuItems(columnId, host)` method (the exported `HeaderMenuContributor` type), found by scanning `host.element.plugins`. In the `fixed` changesets group, so its peer range follows `argus-table`.
- `packages/formulas` (`@argus-table/formulas`, published): formula columns, a plugin built like header-menu (peers `argus-table` and `lit`, `fixed` group, root-node stylesheet `@layer argus-formulas`, per-table state in a `WeakMap`). A column's `formula` (core `ColumnDef.formula`, `<argus-column formula>`; the table itself ignores it) is parsed and compiled once by the DOM-free engine in `src/engine/` (tokenizer, Pratt parser with source spans, spreadsheet coercions, closures with no `eval`, Tarjan for dependency order and cycles); its tests run in Node, the plugin's in the browser (two Vitest projects). The `columns` hook turns each formula column into an ordinary one: an `accessor` that returns `undefined` for an error (so errors sort last), a `cell` that renders errors as `.argus-formula-error` and leaves values to the column's own `cell`, end alignment for numbers and dates, and an `ƒx` header mark. Results are cached per row object; a compiled column is reused while its formula and the identities of what it reads (accessors, other compiled columns) are unchanged, so a re-render keeps the same accessor functions. Columns are named by id, then text header, so it must run before `headerMenu()`. With a `dataSource` formula columns aren't sortable. Whole columns (`[[name]]`, token/node `range`, value `ColumnRange` in `engine/range.ts`) cover the rows `host.filteredIndexes(dependent)` returns, `dependent` being the formula columns using whole columns directly or through others (`Compiled.ranges`), so filters on those don't feed back. The plugin's `willUpdate` compares a key of `data`, the other filters, `quickFilter` and `columnVisibility` and invalidates; the `columns` hook makes the new `rowSource`. Only functions with `ranges` take a `ColumnRange` (else `#VALUE!`); a call using a range but no row value is evaluated `once()`; criteria and lookups go through `engine/range-index.ts` (hash map for equality, sorted copy with running totals for relational number/date criteria, used for `SUMIF` only when the sums are whole numbers). `#N/A` with a `dataSource`. `editing` (`'view'` default, `'edit'`, `'none'`) adds items to the column menu through header-menu's `headerMenuItems` protocol. The editor (`src/editor/`) is loaded with `import()` on first use: `session.ts` (checks, preview, the proposed columns, renaming refs) around `editor.ts` (a modal `<dialog>` rendered with Lit's `render()` into an element the plugin's `columns` hook puts in the header content of the column it opened from, so it takes the table's tokens; a transparent input over a highlighted mirror, a combobox for suggestions). It never sets `columns`: it fires `argus-formula-column-add/-change/-remove` with `detail.columns`, and the app applies them. Size budgets in `.size-limit.js` (esbuild, `lit` and `argus-table` ignored; the dynamic editor imports marked external for the plugin's budget, and measured on their own).

Event detail types come from `@fires {CustomEvent<…>} name` in the element's JSDoc, so every event needs a typed `@fires`. ## Architecture of `<argus-table>`

**TanStack stays internal.** Only `packages/core/src/table/create-table.ts` (and its `sorted-row-model.ts`) imports TanStack Table; it exposes `TableModel`, `ColumnView` and `RowView`. `packages/core/src/types.ts` holds the public types with no TanStack types in them, and `argus-table` re-exports them with `TContent` fixed to `CellContent` (`TemplateResult | Node | string | number`). Never leak TanStack types into the public API. Sorting goes through core's own sorted row model, not TanStack's `createSortedRowModel()`, which is unusably slow in Firefox at scale (see its comment). TanStack caches values on its rows by column id while `data` is the same: when a column keeps its id but gets a new `accessor` (a path or function by identity), `update()` drops those cached values and bumps a per-table version the sorted row model memoizes on (`valuesChanged`). Keep accessor functions stable across re-renders, or every new `columns` array re-reads and re-sorts.

**Shadow DOM structure, light-DOM content (ADR 0001).** The shadow root renders the grid skeleton (header, body rows, cells with `part`s and ARIA). Header and cell _content_ is rendered by `render/cells.ts` (`renderLightDom`, called in `updated()`) into the host's light DOM as direct children with private slot names (`h-{col}`, `c-{poolSlot}-{col}`), so page CSS and the page's own components work inside cells.

**Framework content (ADR 0002, `render/content-directive.ts`).** What `header`/`cell` return goes through the `content()` `AsyncDirective`. Strings, numbers, Lit templates and directive results, nodes and arrays of those render as before (`isForeign()`); anything else is handed to the table's `contentRenderer` (`render(target, content)`, `release(target)`, `flush()`), set by the wrappers. Each part keeps one target (`div.argus-content`, `display: contents`) for its lifetime, so a pooled cell's framework content updates in place. The directive releases on part removal, on a switch to plain content or another renderer, and on table disconnect (the table keeps the light-DOM `RootPart` and calls `setConnected(false)`). Renderers that did work are flushed once per update by `flushContent()` right after `renderLightDom`, before `#measureAutoWidths`: content must be committed synchronously there (React: `flushSync` in `packages/react/src/content.tsx`). Plugins nesting a column's content in their own template wrap it with `host.content()`, or for a column's or group's own header use `host.header(def)` (header-menu, formulas). Wrappers widen `ColumnDef<T, TContent>`'s content type; the React generator types `columns`/`header`/`cell` for React nodes, drops `contentRenderer` from the props and wraps the table in `withContent()`.

**Pooled rows.** `VirtualController` wraps TanStack Virtual and `RowPool`: each rendered row holds a pool slot while in range, freed slots are reused. Body rows and light-DOM content are keyed and ordered by pool slot (not row id), so scrolling updates DOM in place and the node count stays bounded. DOM order is therefore pool order; the logical position is `aria-rowindex` (header = 1, then pinned top rows, then the body; map it with `RowLayout`). The active row is "kept" rendered outside the range so focus survives scrolling. The window has one size from the first render (core `steadyWindow`, the virtualizer's `rangeExtractor`): the most rows that can be visible plus the overscan on both sides, with the overscan that has no room at an end moved to the other side. Keep it that way: WebKit cancels a wheel scroll's animation whenever slot assignment changes inside the scroller, so a pool that grows while scrolling (new rows, new slots) stalls wheel scrolling.

**Update flow** (`argus-table.ts`): `willUpdate` pushes properties into `TableController` → core model, reconciles the active cell, and configures the virtualizer → `render` computes the virtual window and calls the pure render functions in `render/` (`header.ts`, `body.ts`) → `updated` renders light-DOM content, moves focus, and fires deferred events. Row height is measured from a hidden `.probe` element (ResizeObserver), so density and the `--argus-row-height` token drive the virtualizer (with `rowHeight: 'auto'`: the least a row is, and the header's height).

**Row heights** (`rowHeight: 'auto'`, `controllers/virtual-controller.ts`, `controllers/row-measure.ts`, core `virtual/row-sizes.ts`): TanStack Virtual's own measuring recomputes every offset below a measured row (14–23 ms per frame near the top of 1M rows), so in this mode the virtualizer gets `count: 0` and `VirtualController` does the window itself from core's `RowSizes` (a Fenwick tree of differences from the row height, O(log n)), with its own scroll listener and `ResizeObserver` on the scroller. Fixed heights keep the TanStack path unchanged: gate everything on the mode. Heights are kept by row id (`#heights`) and re-indexed when the model's `rowOrder` identity changes (sort, filter, data, a new remote). `RowMeasure.read()` runs in `updated()` after `#measureAutoWidths` (framework content flushed): it reads the height of each loaded body row that shows another row than at its last read (every row after `invalidate()`: a property change, a new column template or row height, a row that grew), with the private `data-measure-row` on those rows (which drops their `min-block-size` for that one read, so rows can shrink) and the pinned groups' heights (→ `--_pin-top-h` / `--_pin-bottom-h`, and `#pinnedPx()` for what scrolls with the body); its `ResizeObserver` requests an update only for a row that grew past its known height. Rows render at their size (`min-block-size`) with `inset-block-start`, rounded up to whole px (even px past 2^24 px: engines place elements only to 2 px there, and fractional heights left gaps). A measured row above the top row keeps the rows in view in place: unscaled, the difference is held (`#hold`, rows render shifted) and written after 150 ms without scrolling, since a write cancels a WebKit wheel scroll; scaled, `ScrollScale.pivot()` bends the mapping instead. Focus waits for the update that places measured rows, and goes through `reveal()` (as when scaled) until rows stop moving. Use `virtual.startOf()` / `sizeOf()` / `pageRows()`, never `index * rowPx`.

**Scroll scaling** (`controllers/virtual-controller.ts`, core `virtual/scroll-scale.ts`): engines limit an element's height (`max-height.ts` measures it once per page, again after a zoom, together with how far a scroller keeps a top-sticky element in place: Firefox lets go of the header past 8.95M px of scrolling, so its cap is 8M px), so a taller body renders at that cap and the scroll position maps linearly onto the rows. TanStack Virtual sees a `Proxy` stand-in for the scroller whose `scrollTop`, `scrollHeight` and `scrollTo()` are logical; rows render at `start` less the logical-minus-physical offset. Under the cap it's the identity. Scroll through the controller (`scrollBy`, `reveal`, `scrollToIndex` with an align and the body's insets), never `scrollTop += px`, and a focused body row is revealed by the controller, not `scrollIntoView` (a physical px is several rows once scaled). Tests force a small cap with `setMaxElementHeightForTests()`.

**Infinite loading** (`dataSource`): `DataController` owns a core `PageCache` (pages loaded / in flight / failed, row count, eviction) and passes it to the model as `remote`; `rowAt()` is then `undefined` for unloaded rows, which render as skeletons. Requests are debounced (50 ms) and aborted when they scroll away; a new source, sort order or `refresh()` starts a fresh cache. Sorting happens on the server in this mode.

**Pinned rows** (`pinnedRows`): separate objects, not data rows; the core model reads them (`pinnedRowAt`, `pinnedCellContext`) outside TanStack's row models. `render/pinned-rows.ts` puts them in two sticky row groups, not pooled. Row positions go through core's `RowLayout` (header, top, body, bottom), so `aria-rowindex` is no longer "row index + 2": use the layout, not arithmetic. The active cell carries its `section`.

**Auto widths** (`width: 'auto'`, `controllers/auto-width.ts`): `measureColumns()` sets a private `data-measure` attribute (`inline-size: max-content`) on the rendered cells of a column, reads their widths and removes it again in one synchronous step in `updated()`. An auto column measures once its first loaded rows render, and the widths go to the core model as `autoWidths`, separate from `columnSizing`. A double-click on a handle and `autosizeColumns()` are resizes: they go through `columnSizing`.

**Column order** (`columnOrder`, `controllers/reorder-drag.ts`): core normalizes the order per pin group, with column groups kept together (`columns/column-order.ts`) and hands it to TanStack as the order of its column defs and pinning arrays (TanStack's ordering feature isn't used: it costs bundle size for nothing). Moves stay within a pin group. A header drag is pointer events on the window (not HTML drag and drop), starts after 4 px, swallows the click that ends it, and changes the order once on drop; Alt+Shift+Arrow moves by one. Headers are keyed by column id, so a moved header loses focus: set `#focusPending`. Announcements go through `announce.ts`, a live region in the document body, because a grid may only own rows.

**`<argus-column>` children** (`argus-column.ts`, `controllers/column-children.ts`): a data-only `ReactiveElement` (no shadow root) that builds a `ColumnDef` from its attributes and properties; a `<template>` child becomes a static cell via Lit's `templateContent`. Columns notify their parent table through a private registry (`watchColumns`) on connect, disconnect and update, so the table has no `MutationObserver` on its children (that would fire on every light-DOM cell render). A non-empty `columns` property wins over the children. `renderLightDom` renders before a private end-marker comment, so children appended later stay outside Lit's part.

**Column groups** (`columnGroups`, `<argus-column-group>`, core `columns/column-groups.ts`; ADR 0003): a separate model over the flat `columns` (plugins, state and events stay flat). `resolveColumnGroups` gives each column its path of groups (`GroupTree.pathOf`); `headerGroupRows` builds the group rows over `model.columns` (top-aligned: a group's level is its depth), splitting a group per pin side and putting `filler` cells over columns without a group at a level (the selection column too). The model memoizes `headerGroups` on a key of what it reads, since views are rebuilt every update. Header rows are `model.headerRows`: `RowLayout` takes them (`header`, `leafHeader`), so the column headers are header row `headerRows - 1`, the body's `aria-rowindex` starts after all of them, and CSS uses `--_header-h` (`--_header-rows` × row height) wherever the header's height counts. Group cells are `columnheader`s with `aria-colspan` and `data-group-key` (no `data-col`, so `gridCell`, `measureColumns`, plugins' `cellOf` and `#activate` skip them); fillers are empty `gridcell`s (an empty `columnheader` fails axe). Group rows aren't virtualized: every group cell renders, slotted `g-{ordinal*3+side}` (stable while scrolling). The active cell on a group is `{ section: 'header', index: level, col }` with `col` a column it covers; `#groupKey` handles keys there, `#headerLevelDown`/`Up` skip fillers, `#reconcileActive` tracks the column headers' row (`#leafLevel`). `normalizeOrder` keeps a group's columns together per pin side; moves are of units (`OrderUnit`: a column, or a group on one side) among `siblingUnits` (same parent group, same side), by `model.nextMove`. Header drags and drop slots work on units too (`HeaderDrag.key`, `unitKey`); a group moves only with `ColumnGroup.reorderable` and its columns' `reorderable`. A group resize (its `resize-handle` with `data-resize-group`, Alt+Arrow, a double-click) is a resize of its resizable columns: `#requestGroupResize` spreads the new total with core `spreadWidth` and goes through `#requestResizes`, so events fire per column. `<argus-column-group>` forwards its children's notifications to its own parent through `column-registry.ts`.

**Row selection** (`selectionMode`, `selection`, event `argus-selection-change`): the rules are pure functions in core `state/selection.ts` (`clickSelection`, `toggleRow`, `selectRange`); the element keeps the state through `controllable()`, a `Set` of it for rendering, and the anchor row id (the last row clicked or toggled without Shift). Ranges go by index in the current order and skip rows whose id is unknown (`dataSource` rows not loaded); select-all is `model.selectableIds()` (loaded rows only for a `dataSource`). Ids are never pruned. Only loaded body rows are selectable: not pinned rows, not skeletons. Presses on interactive cell content don't select (`interactive.ts`, shared with the reorder drag). Selection keys are handled in `#selectionKey` before the arrow-key navigation, which leaves Shift alone. The checkbox column (`selectionCheckboxes`) is a system column view core adds after TanStack resolves (`selectionColumn`, `kind: 'selection'`, id `SELECTION_COLUMN_ID`): it shifts `colIndex` and the start-pinned offsets, and stays out of the column order, sizing, light DOM and click events. Filter `model.columns` by `kind === 'data'` wherever positions in the column order matter (drop slots). Its checkboxes render in the shadow root with `live()`; their click handlers must not `preventDefault()`: for a real click the browser runs the Lit update inside the dispatch, then undoes a cancelled toggle over it.

**Column virtualization** (`virtualizeColumns`, `controllers/column-window.ts`, core `virtual/column-window.ts`): off, every column renders in visual order, keyed by id, slotted by `colIndex` (the DOM as before). On, the scrolling columns in view plus `COLUMN_OVERSCAN` render, from a steady window (`columnWindow` uses `steadyWindow`), and hold slots of a second `RowPool`: renderers get `RenderedColumn`s (`slot` names the light-DOM slots, `key` keys the cells, `place` is the grid column), and cells are in pool order, placed explicitly in row 1 and their column (`grid-area: 1 / colIndex`: with only a column, auto-placement wraps an out-of-order cell into a new grid row); `--_cols` keeps every track. Columns that must render wherever they are go through `#keptColumns()` (the active cell's, a dragged one, auto widths still due, `autosizeColumns()` targets, `scrollToColumn()`'s target, which it measures from its rendered header because flex tracks aren't `width` wide, the first data column with a `dataSource`); pinned and checkbox columns always render. The controller requests an update only when the window moves. Never assume every column has a cell in the DOM: work from `model.columns`, and query only the columns you keep.

**Plugins** (`plugins`, `plugins.ts`, `controllers/plugins.ts`): `ArgusPlugin` has `name` plus optional `connect(host)` (returns a cleanup), `willUpdate(changed, host)`, `columns(defs, host)`, `columnGroups(groups, host)` and `keydown(event, target, host)`. `willUpdate` runs first in the element's `willUpdate` with the changed property names (every property with a value on the first update); `host.invalidateColumns()` there re-runs `columns` in the same update. `PluginController` connects them in array order while the element is connected (cleanup in reverse; reconnects after a move), chains the `columns` and `columnGroups` transforms in `willUpdate` before they reach the model (memoized on input array, plugins array and an invalidation counter, and an output with the same items keeps its identity: core re-resolves on a new array), and offers keys to `keydown` right after the Shift+Tab branch of `#onKeydown`, before every built-in key (not for the checkbox column). Every hook is wrapped: a throw logs `argus-table: plugin "<name>" threw in <hook>` and skips it; a failed `connect` keeps the plugin off until `plugins` changes. The `plugins` setter keeps the old array when the items are the same. `PluginHost` is a closure object over the element's privates (`column`, `columns`, `cellOf`, `setSort` through `#applySorting`, `setPin`, `setHidden`, `setFilter`, `filterValues`, `filteredIndexes` (core `indexesPassing`: data indexes the filters keep, leaving out given columns' filters and quick-filter text; safe to call from an accessor of one of those columns mid-filter), `focusHeader`, `announce`, `invalidateColumns`, `requestUpdate`, `row`, `element`); add capabilities there as required members (plugins get a host, they never implement one, so adding is not breaking; ADR 0004). Hooks see content as `unknown` (`ColumnDef<T, unknown>`): `host.header(def)` resolves a column's or group's own header (a function called, a group's id as fallback) and wraps it, so plugins needn't assert a function `header`'s type. Plugin types are public (`types.ts` re-exports them): no core or TanStack types in them. Header clicks skip `INTERACTIVE` content (including `[popover]` and `dialog`), like reorder and selection, so plugins can put controls in headers.

**Pinning and visibility** (`columnPinning`, `columnVisibility`, events `argus-column-pinning-change` / `argus-column-visibility-change`): override records over `ColumnDef.pin` / `hidden` (`false` unpins or hides, a column not listed keeps its definition). Core resolves the pin and visibility in effect (`pinOf`, `hiddenOf` in `create-table.ts`) and does the grouping, sticky offsets and `pinEdge` itself in `buildViews`: TanStack has no pinning or visibility feature (smaller bundle). Hidden columns stay in TanStack, so they still sort and read; `model.columns` leaves them out and `model.allColumns` lists them with `hidden: true`. A pinned flex column gets a fixed width through the sizing state (`pinnedWidth`). `nextOrder()` positions count the shown columns only (`moveColumn`'s `shown`), so moves step over hidden ones. Users change both only through plugins (`PluginHost.setPin` / `setHidden`, gated by `pinnable` / `hideable`; the last shown column can't be hidden); the event isn't `argus-column-visibility` because the Angular output would shadow the property. A column the active cell was on hands it to the column now in its place (`#columnInPlaceOf`).

**Filtering** (`columnFilters`, `quickFilter`, event `argus-column-filters-change`; core `filters/filter.ts`, `table/filtered-row-model.ts`): `columnFilters` is a record of `ColumnFilter`s by column id (`text`, `number`, `date`, `set`), controllable; `quickFilter` is a plain string property (no event). Pure rules in `filters/filter.ts`: `compileFilter` turns a filter into a value test once, `rowPredicate` combines the column filters (a column's `filterFn` replaces the built-in test) and the quick filter (each word in some shown column's `textOf`) into one row test, `distinctValues` lists a set filter's values under the other filters (`except`). The model rebuilds the predicate when columns, filters, quick filter, visibility or `remote` change and hands it to its own filtered row model, registered in TanStack's `filteredRowModel` slot with a cast (no `columnFilteringFeature`: bundle size, and it reads `row.getValue()`). That model memoizes on the predicate, the core rows and `valueVersion` (bumped by `valuesChanged()`, like sorting) and keeps the same `Row` objects; the sorted model then re-sorts its new source. Remote rows aren't filtered: `DataController` sends `filters` and `quickFilter` in `getRows`, and a filter change resets the cache _without_ the old row count. Users set filters through plugins (`PluginHost.setFilter`, gated by the column's `filter` kind, and `filterValues`); `formulas()` drops `filter` with a `dataSource`, as it does `sortable`. Filtered headers get the part `header-cell-filtered`, `aria-description="Filtered"` and a `filter-indicator` mark; a filter change announces the row count. `#checkAllState`'s cache key includes everything filtering depends on.

**Controlled/uncontrolled state.** `sorting`, `columnSizing`, `columnOrder`, `columnPinning`, `columnVisibility` and `selection` use `controllable()` (`core/src/state/controllable.ts`): uncontrolled until the host sets them; once set, user actions only fire the event with the _proposed_ value; setting `undefined` hands ownership back. Follow this pattern for new user-changeable state, and add it to `TableState` (core `types.ts`), `getState()` and `setState()`. When the table applies a change itself, the event fires after the update completes (`#appliedSort`, `#appliedResize`).

**Saved state** (`getState()`, `setState()`, core `TableState`): `getState()` is a `structuredClone` of every controllable value plus `quickFilter` and `scroll` (`VirtualController.topRow`, a logical index, so it holds under scroll scaling, and `scrollLeft` as a positive `inline` offset), with `version: 1`. `setState()` ignores state with another `version` (silently, like unknown column ids) and reads one without it as version 1; it stores each key through `#restore()`: skipped when controlled or equal as JSON (an equal sort would reload a data source), else `request()` and `requestUpdate(name, old)`, with no `#applied*` entry, so no event fires. `scroll` is applied after the first `updateComplete` (after a data source's jump to the top). A `dataSource` row past `rowCount` while the total is unknown becomes `#scrollTarget`, scrolled to again in `updated()` whenever the row count changes; it's dropped once reached or the total is known, on a new source, sort or filter, and on the user's `wheel`, `touchstart`, `pointerdown` or `keydown` (passive listeners on the host).

**Events** are defined in `events.ts`: `argus-*` names, fired via `fire()` as bubbling, composed `CustomEvent`s, with types added to `HTMLElementEventMap`. Detail types live in core. A change of controllable state fires `argus-<property>-change` with the value under the property's name in `detail` (`{ columnSizing, columnId, width }`), then the cause (ADR 0004): the wrapper generator derives two-way binding from that name (Angular's `<property>Change` output emits the value), and fails on a `…-change` event that matches no property. A resize ends with `argus-column-resize-end` (`#resizing` collects a drag's changes from `startResizeDrag` to its `onEnd`; any other `#requestResizes` call is a whole resize), fired like the change events: after the update, or right away when controlled.

**Keyboard and a11y.** WAI-ARIA grid pattern with a single roving tab stop (`#active`). The host gets `role="grid"` via ElementInternals _and_ a `role` attribute (axe can't see the internals role). Arrow directions and resize keys are logical (RTL-aware via computed `direction`). Pinning uses logical `start`/`end`. Focus scrolls a cell clear of the sticky header, pinned rows and pinned columns through `scroll-margin` on the cells that scroll (`styles/base.ts`), never `scroll-padding` on the scroller: Chromium and WebKit measure sticky cells against the padding, so clicking or focusing a header or pinned-row cell scrolled the body.

**Styling.** No hard-coded colours in components (`styles/base.ts`): every value reads an `--argus-*` token with a neutral fallback (system colours like `Canvas`). Element state is expressed in part names (`cell-sorted`, `cell-pinned-edge`, `row-odd`) because `::part()` can't take attribute selectors. Private CSS variables use the `--_` prefix. Tokens, parts, slots and events are documented in the JSDoc on `ArgusTable` (`@cssprop`, `@csspart`, `@fires`, `@slot`), which feeds the Custom Elements Manifest; keep it in sync.

## Conventions

- Public API (properties, events, `--argus-*` tokens, part names) is a contract; treat additions and changes as API decisions.
- No hard-coded user-visible text (visible text, `aria-label`s, announcements): it goes through the package's labels, `TableLabels` (`packages/table/src/labels.ts`, resolved in `#labels`), `HeaderMenuLabels` (`packages/header-menu/src/labels.ts`) or `FormulasLabels` (`packages/formulas/src/labels.ts`; the editor's defaults in `editor/labels.ts`, loaded with the editor). A new key needs its English default, JSDoc, and its German text in the Features/Labels story (`satisfies` on the full interfaces fails the typecheck otherwise). Text with values is a function of one object (ADR 0005).
- Unit tests sit next to the code (`*.test.ts`); `packages/table/src/test-utils.ts` has `fixture()` (mounts a _sized_ table; virtualization renders nothing in a 0×0 box), `settle()`, `shadow()`, `slotted()`, `scrollTo()`.
- Any change to a published package needs a changeset (CI checks `changeset status`). Write it from the user's point of view; it becomes the changelog entry. Releases go through the "Version packages" PR.
- TypeScript is strict with `noUncheckedIndexedAccess`, `verbatimModuleSyntax` (use `import type`), legacy decorators (`experimentalDecorators`, `useDefineForClassFields: false`), and `.js` extensions in relative imports. ESLint uses `strictTypeChecked` plus lit and wc plugins; template-literal numbers are wrapped in `String()`.
- Project skills (for working on this repo) live in `.claude/skills/`; the public ones for users are in `skills/`. The third-party ones are managed by faehigkeiten via `.faehigkeiten.lock.yaml` (don't edit them by hand); `lit3` isn't in the lock file and is maintained here: it describes how components, controllers, styles and tests are written in this repo, so keep its examples in step with the API.
