# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`<argus-table>`: a framework-agnostic, virtualized data table web component built with Lit 3, TanStack Table v9 (`@tanstack/table-core`) and TanStack Virtual. pnpm + Nx monorepo, Node ≥ 22.12 (`.nvmrc`), pnpm via Corepack. Currently v0.1 (virtualized rows, pinned columns, sorting, resizing, keyboard nav, default theme) plus, for v0.2, `dataSource` infinite loading, pinned rows, auto column widths, column reordering, `<argus-column>` children, the React, Vue and Angular wrappers, the Material-inspired theme, the benchmarks (Storybook "Benchmarks" page, fed by `benchmarks/published/`), scroll scaling past the engines' maximum element height and the StackBlitz starters (`apps/examples`). Phase 3 has started: row selection (`selectionMode`, `selection`), column virtualization (`virtualizeColumns`), column pinning and visibility as state (`columnPinning`, `columnVisibility`), filtering (`columnFilters`, `quickFilter`), the Fluent-inspired, Bootstrap-inspired and minimal themes, and plugin hooks (`plugins`) with the column menu add-on `@argus-table/header-menu` and formula columns with their editor (`@argus-table/formulas`).

`docs/plan/` is the design plan (public API draft, roadmap, architecture diagrams). It describes intended features too, so check the source before assuming something exists (for example `rowHeight: 'auto'` is planned but not implemented). `docs/adr/0001-shadow-vs-light-dom.md` explains the rendering model below.

## Packages

- `packages/core` (`@argus-table/core`, **private, never published**): DOM-free logic, tests run in Node. Column resolution, the TanStack adapter (`table/create-table.ts`), the `controllable` state helper, the `RowPool`. It is bundled into `argus-table`'s build; `packages/table/scripts/check-dist.mjs` fails the build if any `dist` file still imports it. A core change ships as an `argus-table` changeset.
- `packages/table` (`argus-table`, published): the Lit element. Build = Vite library build (ESM, `preserveModules`, lit/TanStack external) + CDN build with everything inlined (`vite.cdn.config.ts`) + bundled `.d.ts` (rollup-plugin-dts) + Custom Elements Manifest (`cem analyze`, from JSDoc on the class) + publint/attw.
- `packages/react` (`@argus-table/react`, published): `@lit/react` components for both elements. `src/generated/elements.ts` is generated and committed: after a change to the element's properties or `@fires` tags, build `argus-table` and run `pnpm --filter @argus-table/react generate` (`lint` fails on a stale file). The generic signatures and type re-exports in `src/index.ts` are hand-written. In the versioning `fixed` group with `argus-table`.
- `packages/vue` (`@argus-table/vue`, published): same layout and `generate` script as React. The generated file is a description of each element plus types in vue-tsc's generic-component shape; `src/define.ts` turns a description into a component (sets element properties itself, emits events and `update:*`, exposes methods). Typecheck is `vue-tsc`, and the tests mount SFCs (`src/test/Declarative.vue` also holds `@vue-expect-error` type checks).
- `packages/angular` (`@argus-table/angular`, published): standalone components on the element tags, generated with `@Input()` setters and `@Output()`s (not `input()`/`output()`: the tests run TestBed in JIT mode in Vitest, which can't see signal inputs without the CLI's transform; for the same reason test hosts use `@ViewChild`). `src/set-property.ts` routes strings to attributes. Built by ng-packagr; `typecheck` also runs `ngc` on `src/test/types.ts` with strict templates. Test mounts call `fixture.detectChanges()` right away so bindings land before the elements' first update.
- `packages/header-menu` (`@argus-table/header-menu`, published): the column menu, a plugin (see Plugins below). It imports only types from `argus-table` (a peer, with `lit`), so it never registers a second element. Its `columns` hook wraps each header in a function that renders the original content, a menu button and, while open, a `popover="auto"` `role="menu"` inside the header's light-DOM content (in the flat tree, so it inherits the table's tokens; in the top layer, so nothing clips it); it's placed with `position: fixed` from the button's rect each frame while open. Per-table state lives in a `WeakMap` keyed by the element, so one plugin instance can serve several tables. Its CSS is a constructable sheet adopted into the table's root node (`@layer argus-header-menu`). Its own items: sort, filter (Filter… opens `filter-form.ts`, a `popover="auto"` `role="dialog"` in the same header content, through `host.setFilter` / `host.filterValues`; typed values apply after 250 ms), pin (`host.setPin`), fit width, hide (`host.setHidden`) and a "Hidden columns" group (`host.columns()`); `headerMenu({ pin, hide, filter })` turns those items off, and labels for hidden columns come from the text headers its `columns` hook saw. Other plugins add menu items with a `headerMenuItems(columnId, host)` method (the exported `HeaderMenuContributor` type), found by scanning `host.element.plugins`. In the `fixed` changesets group, so its peer range follows `argus-table`.
- `packages/formulas` (`@argus-table/formulas`, published): formula columns, a plugin built like header-menu (peers `argus-table` and `lit`, `fixed` group, root-node stylesheet `@layer argus-formulas`, per-table state in a `WeakMap`). A column's `formula` (core `ColumnDef.formula`, `<argus-column formula>`; the table itself ignores it) is parsed and compiled once by the DOM-free engine in `src/engine/` (tokenizer, Pratt parser with source spans, spreadsheet coercions, closures with no `eval`, Tarjan for dependency order and cycles); its tests run in Node, the plugin's in the browser (two Vitest projects). The `columns` hook turns each formula column into an ordinary one: an `accessor` that returns `undefined` for an error (so errors sort last), a `cell` that renders errors as `.argus-formula-error` and leaves values to the column's own `cell`, end alignment for numbers and dates, and an `ƒx` header mark. Results are cached per row object; a compiled column is reused while its formula and the identities of what it reads (accessors, other compiled columns) are unchanged, so a re-render keeps the same accessor functions. Columns are named by id, then text header, so it must run before `headerMenu()`. With a `dataSource` formula columns aren't sortable. `editing` (`'view'` default, `'edit'`, `'none'`) adds items to the column menu through header-menu's `headerMenuItems` protocol. The editor (`src/editor/`) is loaded with `import()` on first use: `session.ts` (checks, preview, the proposed columns, renaming refs) around `editor.ts` (a modal `<dialog>` rendered with Lit's `render()` into an element the plugin's `columns` hook puts in the header content of the column it opened from, so it takes the table's tokens; a transparent input over a highlighted mirror, a combobox for suggestions). It never sets `columns`: it fires `argus-formula-column-add/-change/-remove` with `detail.columns`, and the app applies them. Size budgets in `.size-limit.js` (esbuild, `lit` and `argus-table` ignored; the dynamic editor imports marked external for the plugin's budget, and measured on their own).
- `tools/generate-wrappers` (private): reads `packages/table/dist/custom-elements.json` and writes each wrapper's generated file. Event detail types come from `@fires {CustomEvent<…>} name` in the element's JSDoc, so every event needs a typed `@fires`. Runs from source with Node's type stripping (`.ts` imports).
- `packages/themes` (`@argus-table/themes`): plain CSS in `src/`, built by Lightning CSS (`scripts/build.mjs`). Themes only set `--argus-*` tokens and `::part()` rules.
- `apps/storybook`: stories double as docs and tests (play functions + axe on every story). Each feature gets a story.
- `apps/playground`: the page that e2e, visual tests and `benchmarks/` drive. With `?bench` it leaves the table unmounted until `__argusBench.mount()`.
- `apps/examples`: the StackBlitz starters (`html`, `react`, `vue`, `angular`) and the `examples` project that smoke-tests them. The starters are standalone npm apps outside the pnpm workspace (`apps/*` doesn't match nested folders) with real `^x.y.z` ranges: `scripts/sync-versions.mjs` keeps those at the packages' versions (run by `pnpm version-packages`, checked by `lint`). `smoke` packs the published packages, installs each starter in `.smoke/<name>` against the tarballs with npm, builds it and runs `smoke.spec.ts`. The four data generators must stay identical: the spec computes the expected rows from `html/data.js`.
- `benchmarks/`: `run.ts` measures, `merge.ts` combines per-engine results into `published/` (committed; the Storybook Benchmarks page imports `published/latest.json`).
- `tests/e2e`, `tests/visual`: Playwright projects.

## Architecture of `<argus-table>`

**TanStack stays internal.** Only `packages/core/src/table/create-table.ts` (and its `sorted-row-model.ts`) imports TanStack Table; it exposes `TableModel`, `ColumnView` and `RowView`. `packages/core/src/types.ts` holds the public types with no TanStack types in them, and `argus-table` re-exports them with `TContent` fixed to `CellContent` (`TemplateResult | Node | string | number`). Never leak TanStack types into the public API. Sorting goes through core's own sorted row model, not TanStack's `createSortedRowModel()`, which is unusably slow in Firefox at scale (see its comment). TanStack caches values on its rows by column id while `data` is the same: when a column keeps its id but gets a new `accessor` (a path or function by identity), `update()` drops those cached values and bumps a per-table version the sorted row model memoizes on (`valuesChanged`). Keep accessor functions stable across re-renders, or every new `columns` array re-reads and re-sorts.

**Shadow DOM structure, light-DOM content (ADR 0001).** The shadow root renders the grid skeleton (header, body rows, cells with `part`s and ARIA). Header and cell _content_ is rendered by `render/cells.ts` (`renderLightDom`, called in `updated()`) into the host's light DOM as direct children with private slot names (`h-{col}`, `c-{poolSlot}-{col}`), so page CSS and the page's own components work inside cells.

**Pooled rows.** `VirtualController` wraps TanStack Virtual and `RowPool`: each rendered row holds a pool slot while in range, freed slots are reused. Body rows and light-DOM content are keyed and ordered by pool slot (not row id), so scrolling updates DOM in place and the node count stays bounded. DOM order is therefore pool order; the logical position is `aria-rowindex` (header = 1, then pinned top rows, then the body; map it with `RowLayout`). The active row is "kept" rendered outside the range so focus survives scrolling. The window has one size from the first render (core `steadyWindow`, the virtualizer's `rangeExtractor`): the most rows that can be visible plus the overscan on both sides, with the overscan that has no room at an end moved to the other side. Keep it that way: WebKit cancels a wheel scroll's animation whenever slot assignment changes inside the scroller, so a pool that grows while scrolling (new rows, new slots) stalls wheel scrolling.

**Update flow** (`argus-table.ts`): `willUpdate` pushes properties into `TableController` → core model, reconciles the active cell, and configures the virtualizer → `render` computes the virtual window and calls the pure render functions in `render/` (`header.ts`, `body.ts`) → `updated` renders light-DOM content, moves focus, and fires deferred events. Row height is measured from a hidden `.probe` element (ResizeObserver), so density and the `--argus-row-height` token drive the virtualizer.

**Scroll scaling** (`controllers/virtual-controller.ts`, core `virtual/scroll-scale.ts`): engines limit an element's height (`max-height.ts` measures it once per page, again after a zoom), so a taller body renders at that cap and the scroll position maps linearly onto the rows. TanStack Virtual sees a `Proxy` stand-in for the scroller whose `scrollTop`, `scrollHeight` and `scrollTo()` are logical; rows render at `start` less the logical-minus-physical offset. Under the cap it's the identity. Scroll through the controller (`scrollBy`, `reveal`, `scrollToIndex`), never `scrollTop += px`, and a focused body row is revealed by the controller, not `scrollIntoView` (a physical px is several rows once scaled). Tests force a small cap with `setMaxElementHeightForTests()`.

**Infinite loading** (`dataSource`): `DataController` owns a core `PageCache` (pages loaded / in flight / failed, row count, eviction) and passes it to the model as `remote`; `rowAt()` is then `undefined` for unloaded rows, which render as skeletons. Requests are debounced (50 ms) and aborted when they scroll away; a new source, sort order or `refresh()` starts a fresh cache. Sorting happens on the server in this mode.

**Pinned rows** (`pinnedRows`): separate objects, not data rows; the core model reads them (`pinnedRowAt`, `pinnedCellContext`) outside TanStack's row models. `render/pinned-rows.ts` puts them in two sticky row groups, not pooled. Row positions go through core's `RowLayout` (header, top, body, bottom), so `aria-rowindex` is no longer "row index + 2": use the layout, not arithmetic. The active cell carries its `section`.

**Auto widths** (`width: 'auto'`, `controllers/auto-width.ts`): `measureColumns()` sets a private `data-measure` attribute (`inline-size: max-content`) on the rendered cells of a column, reads their widths and removes it again in one synchronous step in `updated()`. An auto column measures once its first loaded rows render, and the widths go to the core model as `autoWidths`, separate from `columnSizing`. A double-click on a handle and `autosizeColumns()` are resizes: they go through `columnSizing`.

**Column order** (`columnOrder`, `controllers/reorder-drag.ts`): core normalizes the order per pin group (`columns/column-order.ts`) and hands it to TanStack as the order of its column defs and pinning arrays (TanStack's ordering feature isn't used: it costs bundle size for nothing). Moves stay within a pin group. A header drag is pointer events on the window (not HTML drag and drop), starts after 4 px, swallows the click that ends it, and changes the order once on drop; Alt+Shift+Arrow moves by one. Headers are keyed by column id, so a moved header loses focus: set `#focusPending`. Announcements go through `announce.ts`, a live region in the document body, because a grid may only own rows.

**`<argus-column>` children** (`argus-column.ts`, `controllers/column-children.ts`): a data-only `ReactiveElement` (no shadow root) that builds a `ColumnDef` from its attributes and properties; a `<template>` child becomes a static cell via Lit's `templateContent`. Columns notify their parent table through a private registry (`watchColumns`) on connect, disconnect and update, so the table has no `MutationObserver` on its children (that would fire on every light-DOM cell render). A non-empty `columns` property wins over the children. `renderLightDom` renders before a private end-marker comment, so children appended later stay outside Lit's part.

**Row selection** (`selectionMode`, `selection`, event `argus-row-select`): the rules are pure functions in core `state/selection.ts` (`clickSelection`, `toggleRow`, `selectRange`); the element keeps the state through `controllable()`, a `Set` of it for rendering, and the anchor row id (the last row clicked or toggled without Shift). Ranges go by index in the current order and skip rows whose id is unknown (`dataSource` rows not loaded); select-all is `model.selectableIds()` (loaded rows only for a `dataSource`). Ids are never pruned. Only loaded body rows are selectable: not pinned rows, not skeletons. Presses on interactive cell content don't select (`interactive.ts`, shared with the reorder drag). Selection keys are handled in `#selectionKey` before the arrow-key navigation, which leaves Shift alone. The event isn't `argus-selection-change` because the Angular output `selectionChange` belongs to `[(selection)]`; the generator rejects that collision. The checkbox column (`selectionCheckboxes`) is a system column view core adds after TanStack resolves (`selectionColumn`, `kind: 'selection'`, id `SELECTION_COLUMN_ID`): it shifts `colIndex` and the start-pinned offsets, and stays out of the column order, sizing, light DOM and click events. Filter `model.columns` by `kind === 'data'` wherever positions in the column order matter (drop slots). Its checkboxes render in the shadow root with `live()`; their click handlers must not `preventDefault()`: for a real click the browser runs the Lit update inside the dispatch, then undoes a cancelled toggle over it.

**Column virtualization** (`virtualizeColumns`, `controllers/column-window.ts`, core `virtual/column-window.ts`): off, every column renders in visual order, keyed by id, slotted by `colIndex` (the DOM as before). On, the scrolling columns in view plus `COLUMN_OVERSCAN` render, from a steady window (`columnWindow` uses `steadyWindow`), and hold slots of a second `RowPool`: renderers get `RenderedColumn`s (`slot` names the light-DOM slots, `key` keys the cells, `place` is the grid column), and cells are in pool order, placed explicitly in row 1 and their column (`grid-area: 1 / colIndex`: with only a column, auto-placement wraps an out-of-order cell into a new grid row); `--_cols` keeps every track. Columns that must render wherever they are go through `#keptColumns()` (the active cell's, a dragged one, auto widths still due, `autosizeColumns()` targets, the first data column with a `dataSource`); pinned and checkbox columns always render. The controller requests an update only when the window moves. Never assume every column has a cell in the DOM: work from `model.columns`, and query only the columns you keep.

**Plugins** (`plugins`, `plugins.ts`, `controllers/plugins.ts`): `ArgusPlugin` has `name` plus optional `connect(host)` (returns a cleanup), `columns(defs, host)` and `keydown(event, target, host)`. `PluginController` connects them in array order while the element is connected (cleanup in reverse; reconnects after a move), chains the `columns` transforms in `willUpdate` before the columns reach the model (memoized on input array, plugins array and an invalidation counter, and an output with the same items keeps its identity: core re-resolves on a new array), and offers keys to `keydown` right after the Shift+Tab branch of `#onKeydown`, before every built-in key (not for the checkbox column). Every hook is wrapped: a throw logs `argus-table: plugin "<name>" threw in <hook>` and skips it; a failed `connect` keeps the plugin off until `plugins` changes. The `plugins` setter keeps the old array when the items are the same. `PluginHost` is a closure object over the element's privates (`column`, `columns`, `cellOf`, `setSort` through `#applySorting`, `setPin`, `setHidden`, `focusHeader`, `announce`, `invalidateColumns`, `requestUpdate`, `row`, `element`); add capabilities there as optional members, never break it. Plugin types are public (`types.ts` re-exports them): no core or TanStack types in them. Header clicks skip `INTERACTIVE` content (including `[popover]` and `dialog`), like reorder and selection, so plugins can put controls in headers.

**Pinning and visibility** (`columnPinning`, `columnVisibility`, events `argus-column-pin` / `argus-column-hide`): override records over `ColumnDef.pin` / `hidden` (`false` unpins or hides, a column not listed keeps its definition). Core resolves the pin and visibility in effect (`pinOf`, `hiddenOf` in `create-table.ts`) and does the grouping, sticky offsets and `pinEdge` itself in `buildViews`: TanStack has no pinning or visibility feature (smaller bundle). Hidden columns stay in TanStack, so they still sort and read; `model.columns` leaves them out and `model.allColumns` lists them with `hidden: true`. A pinned flex column gets a fixed width through the sizing state (`pinnedWidth`). `nextOrder()` positions count the shown columns only (`moveColumn`'s `shown`), so moves step over hidden ones. Users change both only through plugins (`PluginHost.setPin` / `setHidden`, gated by `pinnable` / `hideable`; the last shown column can't be hidden); the event isn't `argus-column-visibility` because the Angular output would shadow the property. A column the active cell was on hands it to the column now in its place (`#columnInPlaceOf`).

**Filtering** (`columnFilters`, `quickFilter`, event `argus-column-filter`; core `filters/filter.ts`, `table/filtered-row-model.ts`): `columnFilters` is a record of `ColumnFilter`s by column id (`text`, `number`, `date`, `set`), controllable; `quickFilter` is a plain string property (no event). Pure rules in `filters/filter.ts`: `compileFilter` turns a filter into a value test once, `rowPredicate` combines the column filters (a column's `filterFn` replaces the built-in test) and the quick filter (each word in some shown column's `textOf`) into one row test, `distinctValues` lists a set filter's values under the other filters (`except`). The model rebuilds the predicate when columns, filters, quick filter, visibility or `remote` change and hands it to its own filtered row model, registered in TanStack's `filteredRowModel` slot with a cast (no `columnFilteringFeature`: bundle size, and it reads `row.getValue()`). That model memoizes on the predicate, the core rows and `valueVersion` (bumped by `valuesChanged()`, like sorting) and keeps the same `Row` objects; the sorted model then re-sorts its new source. Remote rows aren't filtered: `DataController` sends `filters` and `quickFilter` in `getRows`, and a filter change resets the cache _without_ the old row count. Users set filters through plugins (`PluginHost.setFilter`, gated by the column's `filter` kind, and `filterValues`); `formulas()` drops `filter` with a `dataSource`, as it does `sortable`. Filtered headers get the part `header-cell-filtered`, `aria-description="Filtered"` and a `filter-indicator` mark; a filter change announces the row count. `#checkAllState`'s cache key includes everything filtering depends on. The event isn't `argus-column-filters-change` because the Angular output `columnFiltersChange` belongs to `[(columnFilters)]`.

**Controlled/uncontrolled state.** `sorting`, `columnSizing`, `columnOrder`, `columnPinning`, `columnVisibility` and `selection` use `controllable()` (`core/src/state/controllable.ts`): uncontrolled until the host sets them; once set, user actions only fire the event with the _proposed_ value; setting `undefined` hands ownership back. Follow this pattern for new user-changeable state. When the table applies a change itself, the event fires after the update completes (`#appliedSort`, `#appliedResize`).

**Events** are defined in `events.ts`: `argus-*` names, fired via `fire()` as bubbling, composed `CustomEvent`s, with types added to `HTMLElementEventMap`. Detail types live in core.

**Keyboard and a11y.** WAI-ARIA grid pattern with a single roving tab stop (`#active`). The host gets `role="grid"` via ElementInternals _and_ a `role` attribute (axe can't see the internals role). Arrow directions and resize keys are logical (RTL-aware via computed `direction`). Pinning uses logical `start`/`end`. Focus scrolls a cell clear of the sticky header, pinned rows and pinned columns through `scroll-margin` on the cells that scroll (`styles/base.ts`), never `scroll-padding` on the scroller: Chromium and WebKit measure sticky cells against the padding, so clicking or focusing a header or pinned-row cell scrolled the body.

**Styling.** No hard-coded colours in components (`styles/base.ts`): every value reads an `--argus-*` token with a neutral fallback (system colours like `Canvas`). Element state is expressed in part names (`cell-sorted`, `cell-pinned-edge`, `row-odd`) because `::part()` can't take attribute selectors. Private CSS variables use the `--_` prefix. Tokens, parts, slots and events are documented in the JSDoc on `ArgusTable` (`@cssprop`, `@csspart`, `@fires`, `@slot`), which feeds the Custom Elements Manifest; keep it in sync.

## Conventions

- Public API (properties, events, `--argus-*` tokens, part names) is a contract; treat additions and changes as API decisions.
- Unit tests sit next to the code (`*.test.ts`); `packages/table/src/test-utils.ts` has `fixture()` (mounts a _sized_ table; virtualization renders nothing in a 0×0 box), `settle()`, `shadow()`, `slotted()`, `scrollTo()`.
- Any change to a published package needs a changeset (CI checks `changeset status`). Write it from the user's point of view; it becomes the changelog entry. Releases go through the "Version packages" PR.
- TypeScript is strict with `noUncheckedIndexedAccess`, `verbatimModuleSyntax` (use `import type`), legacy decorators (`experimentalDecorators`, `useDefineForClassFields: false`), and `.js` extensions in relative imports. ESLint uses `strictTypeChecked` plus lit and wc plugins; template-literal numbers are wrapped in `String()`.
- Project skills live in `.claude/skills/` (managed by faehigkeiten via `.faehigkeiten.lock.yaml`; don't edit them by hand). The `lit3` skill describes how components, controllers, styles and tests are written in this repo.
